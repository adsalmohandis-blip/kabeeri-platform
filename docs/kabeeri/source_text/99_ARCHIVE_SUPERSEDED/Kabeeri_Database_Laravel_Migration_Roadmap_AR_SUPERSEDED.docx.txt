KABEERI Database File 08 — Laravel Migration Roadmap
خريطة تنفيذ Laravel Migrations لقاعدة بيانات KABEERI
هذا الملف يحوّل ملفات قاعدة البيانات السابقة إلى خطة تنفيذ عملية داخل Laravel.
يعتمد هذا الملف على:
01 — Core Kernel Database02 — Kabeeri Cloud Database03 — Kabeeri Frontend Anywhere Database04 — Kabeeri Portable Database05 — Kabeeri Dedicated Database06 — Integration Between The Five Systems07 — Master ERD & Module Database Blueprint
الهدف:
ترتيب بناء قاعدة البيانات خطوة بخطوة بطريقة تمنع تضارب العلاقات، وتسمح بالتوسع، وتحافظ على قابلية التصدير، وتدعم Cloud / Frontend Anywhere / Portable / Dedicated.
1. القاعدة الكبرى في تنفيذ Migrations

3. قواعد عامة لكل Migration
3.1 كل جدول مهم يفضّل أن يحتوي
$table->id();$table->ulid('uuid')->unique();$table->timestamps();
أو UUID بدل ULID حسب القرار النهائي.
3.2 Business tables غالبًا تحتوي
$table->foreignId('organization_id')->constrained()->cascadeOnDelete();$table->foreignId('site_id')->nullable()->constrained()->nullOnDelete();$table->foreignId('company_id')->nullable()->constrained()->nullOnDelete();$table->string('status')->default('active')->index();$table->json('metadata')->nullable();$table->softDeletes();
3.3 لا تضيف كل هذه الأعمدة بشكل أعمى
استخدم فقط المناسب لكل جدول.
4. قواعد Foreign Keys
4.1 Platform Tables
مثل:
countriescurrenciespermissionsplansentitlements
غالبًا لا تحتوي organization_id.
4.2 Tenant Tables
يجب أن تحتوي organization_id أو ترتبط بجدول يحتويه.
4.3 Site Tables
يجب أن تحتوي:
organization_idsite_id
4.4 Company Tables
يجب أن تحتوي:
organization_idcompany_id
4.5 Mall Mirror Tables
قد تحتوي organization_id/company_id nullable لأن بعض المصادر قد تكون خارجية.
5. قواعد Indexes العامة
أضف هذه الفهارس حيث ينطبق:
$table->index('organization_id');$table->index(['organization_id', 'status']);$table->index(['organization_id', 'site_id']);$table->index(['organization_id', 'company_id']);$table->index(['company_id', 'status']);$table->index(['site_id', 'status']);$table->index('created_at');
Slug uniqueness
$table->unique(['site_id', 'slug']);$table->unique(['company_id', 'slug']);$table->unique(['organization_id', 'slug']);
حسب السياق.
6. قواعد JSON
استخدم JSON في
metadatasettingsmanifestpayloaderrorsconfigconditionsactions
لا تستخدم JSON في
moneytax totalsstock quantitiesforeign keysinvoice totalsjournal linespermission assignments

32. Laravel Migration Coding Standards
استخدم
$table->foreignId('organization_id')->constrained()->cascadeOnDelete();$table->foreignId('site_id')->nullable()->constrained()->nullOnDelete();$table->foreignId('company_id')->nullable()->constrained()->nullOnDelete();$table->ulid('uuid')->unique();$table->string('status')->default('active')->index();$table->json('metadata')->nullable();$table->timestamps();$table->softDeletes();
لكن لا تستخدم cascadeOnDelete مع كل شيء
في الجداول المالية أو audit:
$table->foreignId('company_id')->constrained()->restrictOnDelete();
أو nullOnDelete حسب الحالة.
33. Delete Strategy
cascadeOnDelete مناسب لـ
menu_items under menusform_fields under formscart_items under cartstemporary data
restrictOnDelete مناسب لـ
invoicesjournal_entriesstock_movementsverification_reviewslegal records
nullOnDelete مناسب لـ
created_byupdated_byassigned_toauthor_user_id
34. Money Fields Standard
استخدم:
$table->decimal('amount', 15, 2);$table->char('currency_code', 3)->default('EGP');
للكميات:
$table->decimal('quantity', 15, 3);
للتكلفة الدقيقة:
$table->decimal('unit_cost', 15, 4);
35. Status Fields Standard
استخدم string status مع enums في التطبيق.
مثال:
$table->string('status', 50)->default('draft')->index();
ولا تستخدم database enum في البداية لتسهيل التطوير.
36. Final Migration Principle
كل migration يجب أن تجاوب:
من يملك هذا الجدول؟هل هو قابل للتصدير؟هل يظهر في Mall؟هل يحتوي بيانات حساسة؟هل يحتاج audit؟هل يحتاج indexes؟هل يعتمد على جدول سابق؟هل يمكن تشغيله في Cloud وPortable وDedicated؟
37. الخلاصة
Laravel Migration Roadmap هو الجسر بين التصميم النظري والتنفيذ.
القاعدة النهائية:
Build the database in layers, not modules randomly.Every migration must protect ownership, portability, security, and future operating modes.
