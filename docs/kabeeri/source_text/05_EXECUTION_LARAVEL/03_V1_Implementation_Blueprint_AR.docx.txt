0. ملخص تنفيذي
هذا الملف هو نقطة الانتقال من الوثائق المعمارية إلى التنفيذ الفعلي. الهدف ليس بناء Kabeeri كاملًا، بل بناء أصغر نواة مستقرة يمكن استخدامها كموقع شركة بسيط، وفي نفس الوقت تكون جاهزة للتوسع لاحقًا إلى Commerce وRabet وMall وERP وCloud وAI.
• ابدأ بنواة صغيرة مستقرة، لا بمنصة كاملة.
• كل Feature تمر من Schema إلى Migration إلى Model إلى Policy إلى Action إلى UI/API إلى Tests.
• أي جدول أو كود لا يخدم V1 أو يمهد مباشرة لتوسّع مؤكد يتم تأجيله.
• كل تغيير مهم يجب أن يظهر في Activity Log أو Audit Log حسب الحساسية.
• V1 يجب أن ينتج Demo حقيقي: Organization + Site + Pages + Media + Theme + Business Profile Draft + Verification Foundation.

4. مبادئ التنفيذ الحاكمة
المبدأ
التطبيق في الكود
Context-first
أي عملية تسأل: داخل أي Organization؟ أي Site؟ أي Company؟
User لا يتبع شركة واحدة
ممنوع users.company_id أو users.role العالمي. الصلاحيات تأتي من memberships.
Organization هو Customer Account
كل بيانات العميل الأساسية تبدأ من organization_id.
Site ليس Company
Site واجهة رقمية، وCompany كيان تجاري.
Business Profile هو الظهور العام
لا نربط Mall مباشرة بجداول التشغيل الخاصة.
Audit by default
الأحداث الحساسة تذهب إلى audit_logs، والأحداث العامة إلى activity_logs.
Export-ready
كل جدول Tenant مهم يجب أن يحمل organization_id أو يرتبط بجدول يحمله.
Feature Flags
أي موديول أو قدرة غير مستقرة يتم التحكم فيها بـ flag.
No direct module chaos
الموديولات تتكلم عبر Events/Contracts/Actions وليس تعديل جداول بعضها عشوائيًا.

hasOne UserProfile; hasMany OrganizationMembership; hasMany CompanyMembership; morphMany ActivityLog as actor

belongsTo owner User; hasMany Memberships; hasMany Companies; hasMany Sites; hasMany Settings

belongsTo Organization; belongsTo User; morphMany RoleAssignments

Site
belongsTo Organization; belongsTo Company nullable; hasMany ContentEntries; hasMany MediaAssets

belongsToMany Permission; scoped by platform/org/company/site
لا يوجد role global للمستخدم.
MediaAsset
belongsTo Organization; morphMany MediaUsage
لا يخزن URL كامل.
ContentType
belongsTo Site nullable; hasMany ContentFields; hasMany ContentEntries
typed content.

belongsTo Organization/Site; belongsTo ContentType; hasMany Revisions; morphOne SeoMetadata
pages/posts.

16. Git وAI Workflow
الجزء
القاعدة
Branches
main / dev / feature/{feature-name} / fix/{bug-name}.
Commit size
كل commit صغير: migration + model + test، وليس feature ضخمة.
Commit format
feat: add organizations table / test: add organization creation tests / fix: correct site slug uniqueness.
AI usage
AI يساعد في scaffold وtests وreview، لكنه لا يدمج كود بدون مراجعة بشرية.
AI review prompt
اسأل AI: ما المخاطر الأمنية؟ هل يوجد tenant leak؟ هل policy تغطي السياق؟ هل migration قابلة للتصدير؟
Merge gate
لا يدخل main إلا بعد tests وmanual check وmigrations سليمة.

18. Anti-patterns ممنوعة في V1
• إضافة company_id أو role داخل users.
• بناء Commerce أو ERP قبل استقرار Core/CMS/RBAC.
• جعل Business Profile هو Company أو Site.
• نشر أي شيء في Mall مباشرة من جداول العميل بدون mirror/consent لاحقًا.
• تخزين URL كامل للملفات بدل relative path.
• استخدام JSON بدل العلاقات الأساسية.
• تجاوز policies في Filament Resources.
• إضافة AI write actions قبل approval/rollback foundation.
• بناء Visual Builder قبل CMS typed content.
• دمج migration ضخمة تحتوي عشرات الجداول بلا tests.
