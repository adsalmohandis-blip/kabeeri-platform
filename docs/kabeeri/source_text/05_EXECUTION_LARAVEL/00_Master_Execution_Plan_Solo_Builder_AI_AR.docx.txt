KABEERI — Master Execution Plan for Solo Builder with AI
خطة التنفيذ الرئيسية لبناء KABEERI بواسطة مؤسس واحد باستخدام الذكاء الاصطناعي
هذا الملف يحوّل كل ما سبق من:
ملف رئيسي+ 18 ملحقًا تأسيسيًا+ V1 إلى V6
إلى خطة تنفيذ عملية قابلة للتطبيق يوميًا وأسبوعيًا.
الهدف:
بناء Kabeeri بطريقة منظمة، صغيرة، قابلة للاختبار، قابلة للتوسع، ولا تنهار بسبب ضخامة الرؤية أو الاعتماد العشوائي على AI.
1. القاعدة الكبرى
Kabeeri مشروع ضخم جدًا، لكن تنفيذه لا يجب أن يكون ضخمًا في كل خطوة.
القاعدة:
Build the smallest stable corethen expand one controlled layer at a time.
بالعربي:
ابنِ أصغر نواة مستقرة، ثم أضف طبقة واحدة محكومة في كل مرة.
2. الهدف العملي من هذه الخطة
هذه الخطة تجيب على:
أبدأ من أين؟
أبني أي جداول أولًا؟
أبني أي Models؟
أستخدم AI في ماذا؟
أراجع كود AI إزاي؟
أعمل Git commits إزاي؟
متى أعتبر مرحلة خلصت؟
متى أنتقل من V1 إلى V2؟
كيف لا أتوه وسط ERP وMall وAI وMarketplace؟
3. المنهج التنفيذي
3.1 لا تبني Kabeeri كله مرة واحدة
ممنوع:
ابني Kabeeri كامل بكل الموديولات.
المطلوب:
ابني migration واحد.ابني model واحد.ابني policy واحدة.ابني action واحدة.ابني resource واحدة.ابني test واحد.
3.2 كل Feature تمر بـ 8 خطوات
1. Define scope2. Write schema3. Create migration4. Create model5. Create policy/permissions6. Create action/service7. Create UI/API8. Write tests + manual check
3.3 كل يوم له نتيجة صغيرة
أمثلة نتيجة يومية:
جدول organizations يعمل.
إنشاء Organization من UI يعمل.
صلاحية organization.manage تعمل.
Page publish يعمل.
Media upload يعمل.
وليس:
بناء CMS كامل.
بناء ERP كامل.

6. قواعد استخدام AI في البناء
6.1 AI مساعد وليس قائدًا

العلاقات.
الصلاحيات.

6.2 لا تطلب من AI Feature ضخمة
ممنوع:
ابني V1 كامل.
مسموح:
ابني migration لجدول sites حسب schema التالي مع indexes وsoft deletes.
6.3 Prompt Pattern القياسي
استخدم هذا القالب:
أنت Senior Laravel Developer.أريد تنفيذ جزء محدد فقط.السياق: Kabeeri منصة multi-tenant تعتمد على organization_id/site_id/company_id.المطلوب: [وصف صغير]القواعد:- لا تضف features خارج المطلوب.- استخدم Laravel conventions.- أضف validation حيث يلزم.- احترم permissions/policies.- اكتب test أساسي.- لا تستخدم raw SQL إلا للضرورة.Schema:[ضع schema]
6.4 مراجعة كود AI
قبل قبول أي كود AI اسأل:
هل أضاف شيء خارج المطلوب؟هل كسر naming convention؟هل تجاهل permissions؟هل وضع business logic في controller؟هل migration آمنة؟هل العلاقات صحيحة؟هل هناك N+1؟هل توجد tests؟هل فيه security issue؟

29. Security Checklist لكل Feature
هل تحتاج permission؟هل فيها بيانات حساسة؟هل تحتاج audit log؟هل file upload موجود؟هل input sanitized؟هل data scoped by organization/site/company؟هل AI يمكنه الوصول لها؟هل export موجود؟هل يجب تسجيل sensitive access؟
30. Performance Checklist لكل Feature
هل القائمة paginated؟هل توجد indexes؟هل هناك N+1؟هل العملية الثقيلة queued؟هل يمكن caching؟هل query scoped؟
