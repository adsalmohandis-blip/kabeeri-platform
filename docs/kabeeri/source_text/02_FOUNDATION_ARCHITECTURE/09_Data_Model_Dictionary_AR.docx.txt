KABEERI — ملحق 9: قاموس نموذج البيانات الرئيسي
Data Model Master Dictionary
هذا الملحق يحدد أسماء الكيانات والجداول والمفاهيم الأساسية داخل Kabeeri، حتى لا يحدث تضارب بين أجزاء المنصة أثناء التنفيذ.
الهدف:
توحيد لغة النظام قبل بناء V1، بحيث يعرف كل مطور أو AI Assistant أو Module معنى كل كيان، أين يستخدم، وما علاقته بباقي الكيانات.
1. لماذا نحتاج قاموس بيانات؟
Kabeeri تحتوي على أجزاء كثيرة:
CMSCommerceERPRabetKabeeri MallTalent MarketplaceTeamsAI Co-builderLegal VerificationBillingMarketplace
لو لم نثبت أسماء الكيانات مبكرًا، سيظهر تضارب مثل:
Company أم Organization؟Business Profile أم Company Profile؟Employee أم User؟Customer أم User؟Product في Commerce أم Product في ERP؟Service في Mall أم Service في ERP؟Marketplace هل هو الداخلي أم Kabeeri Mall؟
هذا الملف يمنع هذا التضارب.
2. قواعد التسمية العامة
2.1 أسماء الجداول
تستخدم صيغة الجمع.
تستخدم snake_case.
واضحة وغير مختصرة قدر الإمكان.
أمثلة:
usersorganizationssitescompaniesbusiness_profilesprofessional_profilesorganization_membershipscompany_membershipscontent_entriesmedia_assetsverification_requests
2.2 أسماء الموديلات
تستخدم صيغة المفرد.
PascalCase.
أمثلة:
UserOrganizationSiteCompanyBusinessProfileProfessionalProfileOrganizationMembershipCompanyMembershipContentEntryMediaAssetVerificationRequest
2.3 أسماء المفاتيح الأجنبية
صيغة:
entity_id
أمثلة:
user_idorganization_idsite_idcompany_idbusiness_profile_idprofessional_profile_id
2.4 الأعمدة المشتركة
الجداول المهمة تحتوي غالبًا على:
idstatusvisibilitymetadata jsoncreated_atupdated_atdeleted_at optional
2.5 JSON fields
نستخدم JSON فقط عندما تكون البيانات:
إعدادات مرنة.
metadata غير أساسية للبحث.
rules قابلة للتغير.
provider-specific data.
لا نستخدم JSON بدل العلاقات الأساسية.
خطأ:
users.companies json
الصحيح:
company_memberships

21. Relationship Rules
21.1 User vs Customer
User هو حساب.
Customer هو دور تجاري أو سجل عميل.
قد يكون Customer مرتبطًا بـ User أو لا.
21.2 User vs Employee
User هو الشخص.
EmployeeRecord أو CompanyMembership يمثل عمله داخل شركة.
21.3 Company vs BusinessProfile
Company كيان تجاري داخلي.
BusinessProfile ظهوره العام في Kabeeri Mall.
21.4 Site vs BusinessProfile
Site هو موقع.
BusinessProfile صفحة/بروفايل عام في Mall.
قد يرتبطان لكنهما ليسا نفس الشيء.
21.5 Product vs ProductListing
Product هو المنتج داخل Commerce.
ProductListing هو ظهوره داخل Kabeeri Mall.
21.6 Service vs ServiceListing
Service هو تعريف خدمة.
ServiceListing هو ظهورها للبيع أو الطلب داخل Mall.

27. الخلاصة التنفيذية
هذا القاموس يعتمد القرارات التالية:
User = الشخصOrganization = مساحة الإدارةSite = الواجهة الرقميةCompany = الكيان التجاريBusinessProfile = الظهور العام للشركة أو البزنسProfessionalProfile = الظهور المهني للفردMembership = علاقة الفرد بكيانKabeeri Marketplace = السوق الداخلي للتوسعاتKabeeri Mall = السوق الخارجي للجمهورProduct = كيان تجاري داخل CommerceProductListing = ظهور المنتج في MallServiceListing = خدمة معروضة في MallInvoice قد تكون PlatformInvoice أو CustomerInvoice أو SupplierBill حسب السياق
هذا القاموس يجب أن يكون مرجعًا ثابتًا لكل ملفات V1 إلى V6.
