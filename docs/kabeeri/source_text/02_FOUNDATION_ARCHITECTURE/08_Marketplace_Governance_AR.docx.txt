KABEERI — ملحق 8: حوكمة الأسواق Marketplace Governance
ملحق للملف الرئيسي وملاحق التأسيس والتشغيل والترابط والإصدارات والصلاحيات والـ Workflows والـ AI
هذا الملف يحدد قواعد بناء وإدارة الأسواق داخل Kabeeri، لأن لدينا نوعين مختلفين تمامًا من الأسواق:
1. Kabeeri Marketplace   السوق الداخلي لتوسيع المنصة2. Kabeeri Mall   السوق الخارجي العام للجمهور والعملاء
الهدف:
منع الفوضى، حماية المستخدمين، تنظيم النشر، ضبط الثقة، وتحديد قواعد البيع والظهور والمراجعة والتوثيق والعمولات.

3. لماذا نحتاج Governance؟
بدون حوكمة، سيحدث:
Plugins غير آمنة.
Themes بطيئة أو مكسورة.
ERP Modules غير دقيقة.
AI Skills تصل لبيانات حساسة.
Businesses مزيفة.
Services وهمية.
Products مخالفة.
Reviews مزيفة.
Talent profiles غير موثقة.
Disputes كثيرة.
انخفاض الثقة في المنصة.
لذلك كل Marketplace يحتاج:
Submission rulesReview processVerificationPermissionsModerationRatingsPaymentsCommissionsDisputesSuspension rulesAppeals

7. Package Manifest
كل Package يجب أن يحتوي manifest واضح.
مثال:
{  "name": "kabeeri/paymob-payments",  "type": "commerce_app",  "version": "1.0.0",  "publisher": "ADMIT",  "requires": {    "kabeeri": ">=1.0.0",    "php": ">=8.3"  },  "permissions": [    "commerce.order.view",    "commerce.payment.manage",    "customer.read"  ],  "hooks": [    "PaymentReceived",    "OrderCreated"  ],  "settings": true}
8. Permission Disclosure
قبل التثبيت، يجب عرض الصلاحيات بوضوح.
مثال:
This package can:- Read orders- Update payment status- Read customer email- Send payment webhooks
لو الصلاحيات حساسة:
Warning:This package can access financial/payment data.
9. Review Process للسوق الداخلي
9.1 مراحل المراجعة
Submission→ Automated validation→ Security scan→ Permission review→ Code/package review→ Performance review→ Compatibility test→ Documentation review→ Approval / Need changes / Reject
9.2 Automated validation
تفحص:
manifest.
version.
dependencies.
package structure.
forbidden files.
required docs.
9.3 Security review
تفحص:
filesystem access.
database access.
external requests.
secret handling.
dangerous functions.
package signing.
9.4 Performance review
تفحص:
query count.
heavy hooks.
frontend assets size.
cache compatibility.
background jobs.
9.5 Legal/business review
مطلوب خصوصًا لـ:
Tax modules.
Payroll modules.
Payment gateways.
Legal verification modules.
Regulated industry modules.
10. Package Signing
كل package منشور يجب أن يكون signed.
لماذا؟
منع التلاعب.
التأكد من المصدر.
حماية المستخدمين.
منع حقن backdoors.
عناصر التوقيع
Package hashPublisher signatureVersion signatureVerification timestamp
11. Installation Governance
عند التثبيت:
Check compatibilityCheck signatureShow permissionsCheck plan/licenseCreate backup if neededInstall packageRun migrations if approvedActivate packageLog activity
12. Update Governance
عند التحديث:
Show changelogCheck breaking changesCheck permissions changesCreate backupApply updateRun health checkRollback if failedLog update
لو الصلاحيات تغيرت:
Require admin approval again
13. ERP Module Governance

versioning صارم.
audit logs.
no silent data changes.
Payroll/Tax Modules

34. الأخطاء الممنوعة
34.1 لا تفتح Marketplace الداخلي للعامة مبكرًا
قبل package review والتوقيع.
34.2 لا تسمح بـ AI Skill بدون permission disclosure
AI Skills خطيرة وقد تصل لبيانات حساسة.
34.3 لا تفتح Kabeeri Mall بدون moderation
أي سوق عام يحتاج reporting وmoderation.
34.4 لا تجعل كل Business يظهر Verified
التوثيق درجات.
34.5 لا تطلق Unified Cart مبكرًا
ابدأ بـ Lead/Redirect ثم توسع.
34.6 لا تخلط بين Kabeeri Marketplace وKabeeri Mall
الأول يوسع النظام.
الثاني يخدم الجمهور.
35. الخلاصة التنفيذية
Kabeeri لديه سوقان:
Kabeeri Marketplace= توسعة المنصة= Plugins / Themes / Modules / Connectors / AI SkillsKabeeri Mall= شبكة أعمال عامة= Businesses / Services / Products / Talent
كل سوق يحتاج حوكمة مستقلة:
ReviewVerificationPermissionsModerationBillingDisputesReputationSecurity
القاعدة النهائية:
لا Marketplace بدون ثقة، ولا ثقة بدون حوكمة.
