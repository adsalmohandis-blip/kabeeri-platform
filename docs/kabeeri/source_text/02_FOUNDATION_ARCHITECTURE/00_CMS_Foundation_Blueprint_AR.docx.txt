KABEERI CMS — powered by ADMIT
1. الرؤية المختصرة
KABEERI هو CMS حديث يبني على أفضل ما في WordPress، لكنه يعالج مشاكله البنيوية من البداية: الأداء، الأمان، جودة الإضافات، تجربة المطور، تجربة المحرر، التحديثات، والاعتمادية.
الشعار الداخلي للمنتج:
كل مرونة WordPress، بدون فوضى WordPress.
أو:
CMS سريع، آمن، قابل للتوسع، ومصمم للمؤسسات والمبدعين من أول يوم.
2. الاسم والهوية
الصيغ الرسمية

3. المشكلة التي نحلها
WordPress قوي بسبب الإيكوسيستم والسهولة، لكنه يعاني من مشاكل متكررة:
الإضافات تعمل بصلاحيات واسعة بدون sandbox حقيقي.
الأداء يعتمد غالبًا على caching وplugins خارجية.
نظام البيانات مرن جدًا لكنه غير typed، مما يصعب بناء تطبيقات كبيرة منظمة.
التحديثات قد تكسر الموقع بسبب تضارب plugins/themes.
تجربة التطوير مشتتة بين PHP hooks وملفات theme وREST وblocks.
الأمن يعتمد بشدة على جودة إضافات الطرف الثالث.
تجربة التحرير قوية لكنها معقدة لكثير من المستخدمين.
الهجرة إلى بديل صعبة بسبب الاعتماد على plugins وSEO URLs وmedia وmetadata.
Kabeeri يجب أن يعالج هذه النقاط كميزات أصلية وليست إضافات لاحقة.
4. وعد المنتج
Kabeeri يجب أن يقدم:
سرعة أصلية بدون الاعتماد على عشرات إضافات الأداء.
أمان مدمج وامتدادات بصلاحيات محددة.

هجرة سهلة من WordPress.
قابلية استخدام للمواقع الصغيرة والمؤسسات الكبيرة.

12. Plugin System
12.1 هدف نظام البلجنز
نريد مرونة WordPress، لكن بدون خطر أن أي plugin يسيطر على النظام بالكامل.
12.2 Manifest إلزامي
كل plugin يجب أن يحتوي على:
{  "name": "kabeeri-seo",  "displayName": "Kabeeri SEO",  "version": "1.0.0",  "publisher": "ADMIT",  "requires": {    "kabeeri": ">=1.0.0",    "php": ">=8.2"  },  "permissions": [    "content.read",    "content.write",    "settings.seo.write"  ],  "hooks": [    "content.beforePublish",    "render.head"  ],  "routes": [    "/admin/seo"  ]}
12.3 أنواع البلجنز
النوع
أمثلة
Official Plugins
SEO, Forms, Analytics, Backup
Integration Plugins
Stripe, Mailchimp, HubSpot
UI Plugins
Admin widgets, editor blocks
Data Plugins
Import/export, sync
Commerce Plugins
Catalog, checkout, payments
Security Plugins
WAF integration, malware scan
12.4 قيود البلجنز
لا يسمح للبلجن بتعديل ملفات core.
لا يسمح بتنفيذ database queries مباشرة إلا عبر API أو capability خاصة.
لا يسمح بإضافة JS/CSS بدون performance budget.
لا يسمح بجمع بيانات المستخدم بدون disclosure.
لا يسمح بتعطيل التحديثات الأمنية.
كل package يجب أن يكون signed.
12.5 Hooks لكن typed
بدل hooks عشوائية strings فقط، نستخدم typed events:
on("content.beforePublish", async (event) => {  // event.entry typed});
أو في PHP:
Kabeeri::on('content.beforePublish', function (BeforePublishEvent $event) {    // typed event});

37. استراتيجية كسب جمهور WordPress
هدف Kabeeri ليس أن يقول لمجتمع WordPress: “اترك كل ما تعرفه”. الهدف أن يقول لهم:
نفس العقلية التي تحبها في WordPress، لكن ببنية أسرع، أأمن، وأنظف.

37.2 التكنولوجيا الأقرب لجمهور WordPress
التوصية النهائية:
Backend/Core CMS: PHP 8.3+ / LaravelAdmin Dashboard: React + TypeScriptDatabase: MySQL + PostgreSQLCache/Queue: Redis optionalTemplates: Blade-like syntax أو Kabeeri TemplatesPlugins: PHP plugins + JSON manifestThemes: HTML/Blade + theme.json-like configCLI: kabeeri command
37.3 لماذا PHP/Laravel؟
لأن جمهور WordPress يعرف PHP، والاستضافات تدعمه، والوكالات تملك مطورين PHP بالفعل. Laravel يعطي بنية حديثة بدون أن نبتعد عن السوق المستهدف.
Kabeeri يجب أن يكون:
مألوفًا لمطور WordPress.
أسهل في التنظيم من WordPress.
أقوى في الأمان من WordPress.
أسرع بدون تركيب 10 plugins.
قابلًا للاستضافة بسهولة.
37.4 لا نستخدم Node.js كـ core في البداية
Node.js ممتاز، لكن لو جعلناه core سنخسر جزءًا من جمهور WordPress التقليدي بسبب:
اختلاف بيئة التشغيل.
صعوبة self-hosting لبعض العملاء.
احتياج DevOps أكبر.
بعده عن خبرة مطوري WordPress.
لكن نستخدم Node.js في:
build tools
admin frontend
theme asset compilation
developer tooling
optional headless SDK لاحقًا
37.5 تجربة مطور WordPress داخل Kabeeri
مثال Plugin في Kabeeri يجب أن يبدو مألوفًا لكن منظمًا:
<?phpuse KabeeriPluginPlugin;use KabeeriEventsContentBeforePublish;return Plugin::define([    'name' => 'admit-seo-helper',    'displayName' => 'ADMIT SEO Helper',    'version' => '1.0.0',    'permissions' => [        'content.read',        'content.update',        'seo.update'    ],    'setup' => function ($app) {        $app->on(BeforePublish::class, function (BeforePublish $event) {            // Validate SEO fields before publishing        });    }]);
يشبه WordPress في فكرة hooks، لكنه أفضل لأنه:
typed.
permissions واضحة.
manifest واضح.
قابل للفحص قبل التثبيت.
لا يتحكم في النظام بالكامل بدون إذن.

37.7 أهم رسالة تسويقية لجمهور WordPress
لا نقول:
نحن لسنا WordPress.
بل نقول:
بنينا Kabeeri لأننا نحب فكرة WordPress، لكننا تعبنا من البطء، الاختراقات، تضارب البلجنز، والتحديثات المخيفة.
رسائل مباشرة:
بدون فوضى البلجنز.
بدون بطء افتراضي.
بدون تحديثات تكسر الموقع.
بدون dashboard مزدحم.
بدون الاعتماد على 15 plugin لأساسيات الموقع.
هجرة سهلة من WordPress.
PHP-friendly وagency-friendly.

37.10 أهم Product Promise
Kabeeri يحافظ على ما يحبه الناس في WordPress: PHP، الثيمات، البلجنز، لوحة سهلة، وهجرة بسيطة — لكنه يعالج ما يكرهونه: البطء، الاختراقات، تضارب الإضافات، وتحديثات تكسر الموقع.
38. الخلاصة
Kabeeri لا يجب أن يكون نسخة WordPress جديدة. يجب أن يكون CMS حديثًا يتعلم من WordPress:
يحتفظ بالمرونة.
يحتفظ بسهولة الاستخدام.
يحتفظ بفكرة الإضافات والثيمات.
يحتفظ بقربه من PHP ومطوري WordPress.
لكنه يضيف أمانًا حقيقيًا، أداءً افتراضيًا، بنية typed، تحديثات آمنة، وتجربة تطوير منظمة.
أقوى مدخل للسوق:
هاجر من WordPress إلى Kabeeri، واحتفظ بالمحتوى والروابط والـ SEO، واحصل على أداء وأمان أفضل من أول يوم.
