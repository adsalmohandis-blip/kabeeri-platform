KABEERI — ملحق 13: الاختبارات والجودة وDevOps
Testing, QA & DevOps Architecture
هذا الملحق يحدد كيف سيتم اختبار Kabeeri، إدارة جودة الكود، تنظيم الإصدارات، تشغيل البيئات، النسخ الاحتياطي، النشر، مراقبة الأخطاء، وإدارة التطوير خصوصًا إذا كان المؤسس يبني وحده باستخدام AI.
الهدف:
منع Kabeeri من التحول إلى مشروع ضخم غير مستقر بسبب كثرة الموديولات والتغييرات والتوليد بالـ AI.
1. لماذا هذا الملحق مهم؟
Kabeeri ليست تطبيقًا صغيرًا.
Kabeeri ستحتوي على:
CMSCommerceERPRabetKabeeri MallTalent MarketplaceAI Co-builderMarketplacePluginsThemesConnectorsLegal VerificationBillingTeamsWorkflows
أي خطأ صغير في جزء قد يكسر أجزاء أخرى.
أمثلة:
تعديل permissions قد يكشف مستندات قانونية.تعديل orders قد يكسر accounting.تحديث plugin قد يكسر checkout.AI change قد يغير workflow حساس.Migration خاطئة قد تضيع بيانات العملاء.
لذلك الاختبار والجودة ليسوا رفاهية.
2. الفلسفة الأساسية
Kabeeri يجب أن يبنى بأسلوب:
Testable from V1Observable from V1Backup before risky changesSmall releasesRollback-readyAI-assisted but human-reviewed
القاعدة:
أي Feature لا يمكن اختبارها أو تتبعها أو الرجوع عنها تصبح خطرًا على المنصة.
3. مستويات الاختبار المطلوبة
3.1 Unit Tests
تختبر جزءًا صغيرًا من الكود.
أمثلة:
حساب الصلاحيات.
توليد slug.
حساب Trust Score.
تطبيق discount.
فحص visibility.
أدوات مقترحة
Pest أو PHPUnit
3.2 Feature Tests
تختبر flow كامل داخل النظام.
أمثلة:
User creates OrganizationUser creates SiteUser creates PageUser publishes Page
Business submits verification documentsAdmin reviews requestVerification status changes
3.3 Policy / Permission Tests
مهمة جدًا في Kabeeri.
أمثلة:
Editor يستطيع تعديل post ولا يستطيع إدارة billing.
Legal Partner يرى فقط verification request المسند له.
Employee لا يرى payroll.
AI لا ينفذ action لا يملكه المستخدم.
3.4 Integration Tests
تختبر الربط بين موديولات.
أمثلة:
Service Request→ Conversation→ CRM Lead→ Notification
Order Paid→ Invoice→ Inventory movement→ Accounting entry لاحقًا
3.5 Browser / End-to-End Tests
تختبر تجربة المستخدم في المتصفح.
أمثلة:
تسجيل الدخول.
إنشاء موقع.
نشر صفحة.
رفع صورة.
إنشاء منتج.
checkout basic.
أدوات محتملة
Laravel Dusk لاحقًاPlaywright لاحقًا
في V1 يمكن تأجيل E2E الكامل.
3.6 Migration Tests
أي migration يجب أن تعمل على database نظيفة، ولا تكسر بيانات موجودة.
مهم جدًا بسبب تطور V1 إلى V6.
3.7 Package Tests
لـ plugins/themes/modules.
أي package يجب اختباره عند:
install.
activate.
deactivate.
update.
uninstall.
3.8 Security Tests
أمثلة:
unauthorized user cannot access company documents.
CSRF protection works.
file upload restrictions work.
API token scope works.
sensitive access is logged.
3.9 AI Safety Tests
أمثلة:
AI لا ينشر محتوى بدون content.publish.
AI لا يعدل payroll بدون approval.
AI generates plan before applying.
AI action logs created.
rollback point exists.

6. QA Checklists
6.1 Checklist قبل دمج أي Feature
هل feature لها tests؟هل permissions مضافة؟هل activity log موجود؟هل validation موجود؟هل errors واضحة؟هل migration reversible أو آمنة؟هل docs محدثة؟هل لا تكسر أجزاء أخرى؟
6.2 Checklist لأي Public Feature
هل لها visibility؟هل لها moderation status؟هل يمكن الإبلاغ عنها؟هل تظهر بيانات حساسة؟هل SEO مضبوط؟هل تعمل على الموبايل؟
6.3 Checklist لأي Financial Feature
هل يوجد audit log؟هل يوجد approval عند الحاجة؟هل لا يمكن الحذف الصامت؟هل rounding صحيح؟هل currency واضحة؟هل permissions دقيقة؟
6.4 Checklist لأي AI Feature
هل يقرأ أقل سياق ممكن؟هل يتحقق من الصلاحيات؟هل ينتج plan؟هل يوجد preview؟هل يوجد approval؟هل يوجد log؟هل يوجد rollback؟
7. Bug Severity Levels
7.1 Critical
يكسر النظام أو يسبب تسريب بيانات أو فقد بيانات.
أمثلة:
أي مستخدم يرى مستندات شركة أخرى.
حذف بيانات بدون تأكيد.
checkout لا يعمل.
migration تكسر production.
التعامل
إصلاح فوري.
لا release قبل الحل.
7.2 High
Feature مهمة لا تعمل أو خطأ أمني متوسط.
أمثلة:
permissions خاطئة في شاشة admin.
media upload يفشل.
verification status لا يتحدث.
7.3 Medium
خطأ يؤثر على تجربة المستخدم لكن له workaround.
7.4 Low
تحسين أو مشكلة UI بسيطة.

23. AI-assisted Development Rules
بما أن المؤسس سيبني باستخدام AI، يجب اتباع قواعد صارمة.
23.1 لا تقبل كود AI بدون فهم
AI يسرع، لكنه قد ينتج:
ثغرات.
migrations خطيرة.
logic خاطئ.
كود مكرر.
tests ضعيفة.
23.2 كل كود AI يجب أن يمر بـ
ReviewRun testsRun app locallyCheck permissionsCheck migrationsCommit small
23.3 لا تطلب من AI بناء Module ضخم مرة واحدة
قسم العمل:
ModelMigrationPolicyActionControllerViewsTestsDocs
23.4 Prompts للبناء
استخدم prompts محددة:
ابني migration فقط لجدول organizations حسب هذا schema.
أفضل من:
ابني منصة Kabeeri كاملة.
