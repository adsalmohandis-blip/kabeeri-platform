KABEERI Database File 04 — Kabeeri Portable Database
نظام Kabeeri Portable
هذا الملف يصف تصميم قاعدة البيانات الخاص بوضع:
Kabeeri Portable
وهو الوضع الذي يسمح للعميل بأخذ:
الكود+ قاعدة البيانات+ الملفات+ الثيمات+ الموديولات+ إعدادات التشغيل
وتشغيل نسخة كاملة خارج Kabeeri Cloud، مع إمكانية استمرار الظهور داخل Kabeeri Mall عبر Sync Connector.
1. تعريف Kabeeri Portable
Kabeeri Portable هو باقة خروج كاملة من Cloud.
العميل يحصل على نسخة قابلة للتشغيل خارج المنصة:
Self-hosted Kabeeri instance
لكن يمكنه اختيار استمرار العلاقة مع Kabeeri عبر:
Mall SyncVerification continuityTrust profileSupport/updates optional
2. الهدف من Portable
الهدف هو تحقيق 3 أشياء:
2.1 ثقة العميل
العميل لا يشعر أنه محبوس.
2.2 قوة تسويقية ضد WordPress/Shopify
ابدأ Cloud، ولو احتجت تخرج، تقدر تاخد بياناتك وتشغلها بنفسك.
2.3 استمرار العلاقة مع Kabeeri Mall
حتى بعد الخروج، يستطيع العميل تحديث بياناته العامة في Mall.
3. ما الذي يتم تصديره؟

4. ما الذي لا يتم تصديره؟
لا يتم تصدير:
بيانات عملاء آخرينPlatform internal secretsGlobal billing internalsGlobal package catalog الكاملMall moderation internal dataPlatform security keysLegal partner private data غير متعلق بالعميل
5. الفرق بين Portable و Dedicated
Portable
العميل يشغل بنفسه أو عند مزود خارجي.
Dedicated
Kabeeri تدير نسخة مخصصة للعميل.

20. Portable Export Flow
Customer requests export→ permission and plan check→ export_job created→ optional approval→ export registry loaded→ data collected by organization_id→ files collected by tenant folder→ transformations applied→ SQL dump generated→ media zip generated→ manifest generated→ bundle created→ customer downloads→ self-hosted installation optionally registers→ cloud data archived/deleted according to policy→ mall sync remains active if enabled

22. Portable Database Transformation
عند التصدير، يمكن أن نحتاج:
22.1 Keep IDs
لو النسخة ستكون مستقلة تمامًا، يمكن إبقاء IDs كما هي.
22.2 Re-map IDs
لو التصدير يدمج بيانات أو يغير structure، نحتاج mapping.
22.3 Remove Platform-only references
مثل:
platform_subscription_idcloud_site_idbilling internal references
22.4 Preserve UUIDs
الـ UUIDs مهمة للتزامن مع Mall.

26. Mall Sync بعد Portable
بعد خروج العميل، مصدر بيانات Mall يصبح:
self_hosted_installation
بدل Cloud DB.
Flow:
Customer updates product locally→ self-hosted Kabeeri fires event→ MallSyncClient sends signed payload→ Kabeeri validates token→ Mall mirror updates→ sync event logged
27. Mall Sync Payload Rules
Portable لا يرسل بيانات خاصة.
يرسل فقط:
business public profileservices public dataproducts public datatalent public dataavailability/statuspublic URLs
لا يرسل:
orderscustomersinvoicesaccountingprivate inventory costsemployee evaluationsprivate messages

35. الخلاصة
Kabeeri Portable هو أقوى رسالة ثقة للعميل.
لكنه ليس الوضع الافتراضي، بل Premium.
القاعدة النهائية:
Portable gives full ownership to the customer, while Mall Sync keeps the business connected to Kabeeri’s public ecosystem by consent.
