KABEERI Database File 05 — Kabeeri Dedicated Database
نظام Kabeeri Dedicated
هذا الملف يصف تصميم قاعدة البيانات الخاص بوضع:
Kabeeri Dedicated
وهو وضع مخصص للعملاء الكبار أو الجهات الحساسة التي تريد بيئة منفصلة، لكن مع استمرار إدارة Kabeeri أو تكاملها مع المنصة الرئيسية وKabeeri Mall.
1. تعريف Kabeeri Dedicated
Kabeeri Dedicated يعني أن العميل يحصل على بيئة مخصصة:
Dedicated Application+ Dedicated Database+ Dedicated Storage+ Dedicated Queue/Cache optional+ Dedicated Domain+ Optional Dedicated AI/Integration settings
لكنها ليست بالضرورة Self-hosted عند العميل.
قد تكون:
Managed by Kabeeri
أو:
Hosted in customer private cloud with Kabeeri support
2. الفرق بين Dedicated و Portable
Dedicated
Kabeeri غالبًا تدير النسخة أو تشرف عليها.
Portable
العميل يأخذ نسخة ويصبح هو المسؤول الأساسي عن تشغيلها.
3. متى نستخدم Dedicated؟
مناسب لـ:
Enterprise customers.
شركات كبيرة.
جهات حكومية.
قطاعات منظمة.
عملاء يحتاجون Data Residency.
عملاء يريدون performance isolation.
عملاء لديهم حجم بيانات كبير.
4. أهداف Dedicated Database
يجب أن يدعم:
بيئة منفصلة للعميل.
بيانات معزولة في DB منفصلة.
ربط اختياري مع المنصة الرئيسية.
Mall Sync آمن.
تحديثات مُدارة.
Backups مخصصة.
Monitoring.
Security policies أعلى.
إمكانية التحول من Cloud إلى Dedicated.
إمكانية التحول من Dedicated إلى Portable إذا لزم.
5. Dedicated Deployment Models
5.1 Kabeeri Managed Dedicated
Kabeeri hosts and manages everything
5.2 Customer Cloud Dedicated
Customer provides cloud/serverKabeeri deploys/supports
5.3 Hybrid Dedicated
Core app dedicatedMall/verification/billing remain connected to Kabeeri Central

22. Dedicated Provisioning Flow
Enterprise customer signs plan→ organization exists or created→ dedicated_tenant created→ dedicated_environment production created→ database provisioned→ storage provisioned→ domain configured→ access key issued→ migration/import from Cloud optional→ health checks pass→ tenant status active
23. Migration from Cloud to Dedicated
Cloud organization selected→ freeze or schedule migration window→ backup Cloud data→ export tenant data→ import into Dedicated DB→ verify counts/checksums→ switch domain/routing→ enable dedicated sync→ update cloud status to migrated_to_dedicated
24. Dedicated Database داخليًا
داخل قاعدة بيانات العميل المخصصة، يمكن استخدام نفس Schema الخاص بـ Core وModules.
الفرق:
قد تبقى organization_id موجودة حتى لو هناك عميل واحد
لماذا؟
لتوحيد الكود.
لتسهيل الرجوع إلى Cloud.
لدعم multi-company داخل Dedicated.
لدعم agency/enterprise structures.
25. Dedicated و Kabeeri Mall
Dedicated لا يتصل مباشرة بجداول Mall، بل عبر Sync.
Dedicated Instance→ Dedicated Access Key→ Mall Sync API→ Mall Mirror→ Public Kabeeri Mall
26. Dedicated و Billing
Billing قد يبقى في Central Kabeeri.
Dedicated instance قد يرسل usage summaries فقط:
users_countsites_countstorage_usageai_usagesync_events
ولا يرسل بيانات خاصة.
27. Dedicated و Security
Dedicated يجب أن يدعم:
privileged support access.
temporary access approval.
audit logs.
encrypted credentials.
isolated backups.
health reports.
SIEM integration for enterprise.
28. Dedicated Support Access Flow
Kabeeri support requests access→ customer admin approves→ temporary token issued→ support actions logged→ access expires automatically

33. Dedicated و Portable
Dedicated يمكن أن يتحول إلى Portable لو العميل يريد السيطرة الكاملة.
Flow:
Dedicated export→ portable bundle→ revoke managed access optional→ self_hosted_installation registered
34. Dedicated Release Requirements
Dedicated يعتبر جاهزًا عندما:
dedicated tenant can be createdenvironments can be registereddedicated database metadata stored safelyaccess keys issued and revokedhealth checks workbackup policies workupdate logs worksupport access request worksmall sync works via dedicated access keycloud to dedicated migration path documented
35. الخلاصة
Kabeeri Dedicated هو خيار Enterprise قوي.
يعطي العميل عزلًا أعلى دون فقدان العلاقة مع Kabeeri.
القاعدة النهائية:
Dedicated isolates the customer’s runtime, while keeping a controlled bridge to Kabeeri Central for Mall, billing, updates, support, and trust.
