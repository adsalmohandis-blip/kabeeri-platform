KABEERI Database File 03 — Kabeeri Frontend Anywhere Database
نظام Kabeeri Frontend Anywhere
هذا الملف يصف تصميم قاعدة البيانات الخاص بوضع:
Kabeeri Frontend Anywhere
وهو وضع يسمح للعميل أن يستضيف الواجهة العامة لموقعه في أي مكان يريده، مع بقاء:
Control PanelDatabaseCMSCommerceERPAIMall Sync
داخل Kabeeri Cloud.
1. تعريف Frontend Anywhere
Frontend Anywhere يعني:
العميل يملك حرية استضافة الواجهة العامة خارج Kabeeriلكن مصدر البيانات ولوحة التحكم يظلان داخل Kabeeri Cloud
أمثلة الواجهة:
Static HTML export.
Next.js frontend.
Nuxt frontend.
Astro frontend.
Custom frontend.
CDN-hosted frontend.
Agency-built frontend.
2. هدف هذا النظام
الهدف هو إعطاء العميل مرونة كبيرة في الواجهة بدون تحميله عبء إدارة Backend وDatabase.
هذا الوضع مناسب جدًا لـ:
وكالات التصميم.
مواقع محتوى عالية الأداء.
شركات تريد Frontend مخصص.
عملاء يريدون استضافة الواجهة على CDN خاص.
مواقع تحتاج أداء عالي لكن Admin مُدار.

19. Frontend Anywhere Flow
Site exists in Kabeeri Cloud→ User enables Frontend Anywhere→ frontend_project created→ API key generated→ scopes selected→ external frontend connected→ domain configured externally→ frontend reads public APIs or static snapshots→ updates trigger cache invalidation/webhook
20. Data Access Pattern
Frontend Anywhere يجب أن يستخدم واحدًا من 3 أنماط:
20.1 API Mode
الواجهة تسحب البيانات من Kabeeri APIs.
20.2 Static Snapshot Mode
Kabeeri يولد ملفات JSON/HTML static.
20.3 Hybrid Mode
المحتوى static، والطلبات مثل forms/cart ديناميكية عبر API.
21. Public API Data Contract

22. Frontend Anywhere و Kabeeri Mall
في هذا الوضع، Mall Sync لا يحتاج Pipeline خارجي معقد لأن البيانات الأصلية لا تزال داخل Kabeeri Cloud.
Admin updates product in Kabeeri→ Product updated in Cloud DB→ Mall mirror updates internally→ Frontend external receives webhook/cache invalidation
23. Cache Invalidation Flow
ContentPublished→ create frontend_cache_invalidations→ send webhook to frontend_project→ update snapshot if static mode→ frontend rebuilds or clears cache
24. Form Submission Flow
Visitor submits form on external frontend→ POST to Kabeeri public API→ validate API key/scope→ create form_submission→ notify admin→ optional lead creation
25. Commerce Flow في Frontend Anywhere
Option A — Headless Cart
External frontend uses Kabeeri cart/order API
Option B — Catalog Only
Products shown externallyorder/request happens inside Kabeeri or Mall
Option C — Redirect
External frontend redirects to Kabeeri checkout
في V1 لهذا النظام، الأفضل:
Catalog + Forms + Service Requests
ثم cart/order لاحقًا.

29. Frontend Anywhere vs Portable
Frontend Anywhere
DB عند KabeeriAdmin عند KabeeriFrontend فقط خارجي
Portable
DB عند العميلAdmin عند العميلFrontend عند العميلSync مع Mall عبر Connector
