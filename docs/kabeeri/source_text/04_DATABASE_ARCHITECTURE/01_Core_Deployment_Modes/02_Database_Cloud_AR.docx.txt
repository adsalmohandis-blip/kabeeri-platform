KABEERI Database File 02 — Kabeeri Cloud Database
نظام Kabeeri Cloud
هذا الملف يصف تصميم قاعدة البيانات الخاص بوضع:
Kabeeri Cloud Managed
وهو الوضع الافتراضي للمنصة، حيث تكون:
الواجهة+ لوحة التحكم+ قاعدة البيانات+ الملفات+ التحديثات+ الموديولات+ Mall Sync+ AI+ Billing
كلها مُدارة داخل Kabeeri Cloud.
1. هدف Kabeeri Cloud Database
هدف نظام Cloud هو توفير بيئة SaaS مُدارة بالكامل تسمح للعميل أن يبدأ بسرعة بدون إدارة Hosting أو DB أو تحديثات.
يجب أن يدعم:
إنشاء مواقع Cloud.
ربط Domains.
إدارة SSL status.
خطط وأسعار.
اشتراكات.
حدود استخدام.
تخزين ملفات.
نسخ احتياطي.
Health checks.
Entitlements.
Mall integration داخلي مباشر.
الانتقال لاحقًا إلى Frontend Anywhere أو Portable أو Dedicated.
2. موقع Cloud داخل المعمارية العامة
Kabeeri Cloud يعتمد على Core Kernel.
Core Kernel→ Organization→ Site→ Company→ Cloud Site→ Subscription→ Entitlements→ Usage→ Backups→ Mall Mirror
3. مبادئ تصميم Cloud
3.1 Cloud هو Default Mode
كل عميل جديد يبدأ غالبًا في Cloud.
3.2 Cloud لا يمنع الخروج
رغم أن البيانات داخل المنصة، يجب أن تكون قابلة للتصدير لاحقًا.
3.3 Cloud هو أفضل تكامل مع Mall
لأن بيانات العميل موجودة أصلًا داخل Kabeeri.
3.4 Cloud يحتاج Billing/Entitlements قوي
حتى لا تصبح تكلفة التشغيل مفتوحة.

24. Cloud Provisioning Flow
User registers→ creates organization→ chooses plan→ billing account created→ subscription created→ entitlements applied→ site created→ cloud_site created→ subdomain reserved→ default theme applied→ health check runs→ site becomes active
25. Domain Flow
User adds custom domain→ cloud_domains record created→ verification token generated→ DNS instructions shown→ verification check runs→ SSL status updated→ domain becomes active
26. Backup Flow
Manual or scheduled backup→ cloud_backups record created→ queue job runs→ database/files snapshot created→ checksum stored→ user notified
27. Entitlement Check Flow
أي Feature مهمة يجب أن تمر عبر:
EntitlementService
مثال:
Can organization create another site?Can site enable commerce?Can user export portable bundle?Can business publish in Mall?
28. Cloud و Kabeeri Mall
في Cloud الوضع الأفضل لأن البيانات داخل المنصة.
لذلك Mall Sync يكون داخليًا:
BusinessProfileUpdated→ update mall mirrorProductPublished→ update mall listingServicePublished→ update mall service listing
لا نحتاج API خارجي إلا عند الانتقال إلى Portable أو External systems.

35. الخلاصة
Kabeeri Cloud هو الوضع الافتراضي والأقوى تكامليًا.
لكنه لا يجب أن يكون قفصًا.
القاعدة النهائية:
Cloud gives the best experience, but the database must remain export-ready from day one.
