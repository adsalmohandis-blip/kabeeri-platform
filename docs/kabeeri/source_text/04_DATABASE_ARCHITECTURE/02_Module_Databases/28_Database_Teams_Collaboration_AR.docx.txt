Kabeeri Teams / Collaboration Database
قاعدة بيانات Kabeeri Teams والتعاون الداخلي المرتبط بالعمل
1. تعريف Kabeeri Teams
Kabeeri Teams هو نظام التعاون الداخلي داخل Kabeeri، لكنه ليس نسخة كاملة من Slack. هدفه ربط المحادثات بالعمل الفعلي داخل المنصة: العملاء، الطلبات، الفواتير، المشاريع، التوثيق، المحتوى، المنتجات، الدعم، الموافقات، والتنبيهات النظامية.
القاعدة الأساسية: كل محادثة مهمة يجب أن تعرف السياق الذي تخدمه: Organization أو Company أو Site أو Object محدد داخل CMS / Commerce / ERP / Rabet / Mall.
2. الهدف من قاعدة بيانات Teams
تمكين القنوات الداخلية والرسائل المباشرة داخل Organization وCompany.
ربط النقاشات بسجلات العمل مثل Order أو Invoice أو Lead أو Task أو Project أو Verification Request.
تحويل رسالة إلى Task أو Approval أو Follow-up بدون نسخ البيانات بين الأنظمة.
إرسال System Alerts من الموديولات مثل orders, verification, billing, security, support.
حماية الخصوصية والصلاحيات بحيث لا يرى المستخدم إلا قنوات وسياقات مسموحة له.
تجهيز النظام للتوسع لاحقًا إلى Collaboration Advanced في V5 وFull Team Collaboration Suite في V6.

Full Slack replacement.
Apps داخل Teams.
Advanced search داخل Teams.
Full external guest collaboration.
Enterprise eDiscovery الكامل.
Data residency per-channel.
Chat bots marketplace المفتوح.
5. مبادئ التصميم
Work-linked collaboration: المحادثات تخدم كيان عمل أو سياقًا واضحًا.
Context-first permissions: صلاحية رؤية الرسالة لا تأتي من Teams فقط، بل من السياق المرتبط بها.
Tenant-scoped by default: كل شيء يحتوي organization_id، وعند الحاجة company_id / site_id.
No private data leakage: لا تظهر محادثات payroll أو finance أو legal documents إلا بصلاحيات صريحة.
Messages are records: لا يتم حذف الرسائل الحساسة حذفًا صامتًا؛ يجب وجود revisions/logs أو retention policy.
Attachments use Media/Files layer: Teams لا يخزن الملفات نفسها، بل يربط بـ media_assets أو documents.
Notifications are routed: mentions وsystem alerts تمر عبر Notification Center.

34. Default Channels Flow
Company activates Teams V1.
Create team_workspace for company.
Create default channels: #general, #orders, #verification, #billing, #security, #support.
Add company owner/admins as channel admins.
Create team_system_alert_channels for module alerts.
Create notification routing rules.
Log activity: teams_workspace_created and channels_created.
35. Message Flow
User opens allowed channel or DM.
Backend checks organization/company/site permissions and channel membership.
Message is stored in team_messages.
Mentions are parsed into team_message_mentions.
Attachments are stored through Media/Files and linked in team_message_attachments.
Notifications are created for mentioned users or channel subscribers.
Search index receives a safe indexed copy according to visibility.
36. Task from Message Flow
User selects message and chooses Create Task.
System checks task.create permission in the linked context.
Task is created in Tasks/ERP module.
team_tasks_from_messages stores message_id → task_id.
Message gets system reply: task created.
Activity log records task_created_from_message.
37. Approval from Chat Flow
A quotation, purchase request, verification step, or AI plan requires approval.
Workflow creates approval_request.
Teams posts an approval message in the linked channel/thread.
Approver clicks approve/reject; decision is written to approval_decisions, not only team_messages.
team_approval_links keeps the link between message and approval request.
Final decision triggers workflow event and audit log.
38. System Alert Flow
Event occurs: OrderCreated, InvoiceOverdue, VerificationNeedsInfo, SecurityEventDetected.
Event listener checks team_alert_rules.
System creates team_messages with sender_type = system.
Mentions or notification rules trigger Notification Center.
If channel is readonly, only system/bot messages are allowed.
39. Object-linked Discussion Rules
أي نقاش مرتبط بفاتورة يجب أن يفحص finance/invoice permissions.
أي نقاش مرتبط بتوثيق قانوني يجب أن يفحص verification/document permissions.
أي نقاش مرتبط بتقييم موظف لا يظهر في channels العامة.
أي object discussion يتم أرشفته مع object history ولا يحذف بصمت.
team_object_links هو الرابط الرسمي بين الدردشة والعمل.

41. Roles المقترحة
Team Workspace Owner: يدير workspace والقنوات الافتراضية.
Channel Admin: يدير قناة محددة وأعضائها.
Team Member: يرسل رسائل ويشارك في القنوات المسموحة.
Guest / External Collaborator: وصول محدود لقنوات محددة فقط.
System Bot: يرسل alerts من الموديولات.
Compliance Viewer: يرى exports/access logs حسب policy.
42. علاقة Teams مع Notification Center
mentions تولد notification للعضو المذكور.
system alerts قد تظهر في Teams وNotification Center معًا.
DMs يمكن أن تعتمد على نفس مفهوم conversations لكن بواجهة Teams.
التنبيهات الخارجية مثل email/push لا تخرج مباشرة من Teams؛ تمر عبر Notification Delivery.
43. علاقة Teams مع Search
رسائل Teams يمكن فهرستها في search index خاص داخلي فقط.
لا يتم فهرسة القنوات الخاصة للعامة أو Mall.
أي نتيجة search يجب أن تفحص membership + context permission.
Advanced search ليس جزءًا من V4، لكن تصميم الفهرسة يسمح به لاحقًا.
44. علاقة Teams مع AI
AI يمكنه تلخيص thread إذا كان المستخدم يملك صلاحية قراءة كل الرسائل.
AI لا يستخدم رسائل finance/legal/hr الحساسة بدون data classification check.
AI-generated summary يتم تخزينه كرسالة ai_summary أو كمرفق تقرير حسب السياسة.
أي Action من AI داخل Teams يظل خاضعًا لـ Plan/Preview/Approval/Rollback.
45. علاقة Teams مع Portable / Dedicated / Frontend Anywhere
النظام
القواعد
Cloud
Teams يعمل بالكامل داخل Kabeeri Cloud ويستخدم نفس DB وMedia وNotifications.
Frontend Anywhere
الواجهة العامة خارجية؛ Teams لا يخرج، لأن Admin/DB داخل Cloud.
Portable
يمكن تصدير Teams حسب policy. الرسائل الحساسة قد تستثنى أو تؤرشف. يجب الحفاظ على UUIDs للروابط.
Dedicated
Teams يعمل داخل Dedicated DB، مع إمكانية إرسال usage/security summaries فقط للمركز.
Mall Sync
Teams لا يرسل محادثات خاصة إلى Mall. فقط leads/inquiries العامة تمر عبر Inbox/Mall حسب consent.

47. Security Requirements
كل قراءة رسالة تمر عبر TeamAccessService.
القنوات الخاصة لا تعتمد على UI hiding فقط.
attachments الحساسة تستخدم signed URLs وسجلات access.
delete_any يحتاج صلاحية صريحة ويسجل audit log.
export conversations يحتاج approval في القنوات الحساسة.
legal/finance/hr channels يمكن فرض retention وlegal hold.
system bot لا يستطيع إرسال رسالة في قناة غير مصرح بها module-wise.

52. الخلاصة التنفيذية
قاعدة بيانات Kabeeri Teams يجب أن تبني تعاونًا داخليًا مرتبطًا بالعمل، لا دردشة عامة منفصلة. أهم قيمة هي أن كل قناة ورسالة يمكن ربطها بسياق حقيقي داخل Kabeeri: طلب، عميل، فاتورة، مشروع، توثيق، محتوى، أو تنبيه أمني. لذلك Teams يعتمد على Core permissions وNotifications وMedia وEvents/Workflows وTasks/Approvals، ويمهد لاحقًا لـ Team Collaboration Advanced في V5 وFull Team Collaboration Suite في V6.
