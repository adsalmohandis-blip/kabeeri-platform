Kabeeri Agency Platform Database
نظام قاعدة بيانات منصة الوكالات وإدارة عملاء الوكالة
هذا الملف يصف تصميم قاعدة البيانات الخاص بطبقة Kabeeri Agency Platform، وهي الطبقة التي تسمح للوكالات بإدارة مواقع ومؤسسات عملائها، متابعة الحالة، تدوين الصيانة، منح العميل وصولًا محدودًا، وتجهيز أساس white-label بدون خلطها مع Cloud أو Billing أو Sites.
1. تعريف Agency Platform
Agency Platform هي مساحة تشغيل مخصصة للوكالات التي تدير عدة عملاء ومواقع داخل Kabeeri. الوكالة ليست مالكة بيانات العميل بالضرورة، لكنها قد تملك صلاحيات إدارة أو دعم أو صيانة أو فوترة حسب الاتفاق.
الوكالة يمكن أن تكون Organization من نوع agency.
العميل يمكن أن يكون Organization مستقلًا تديره الوكالة بصلاحيات محددة.
الموقع يظل داخل sites / cloud_sites أو Frontend Anywhere / Dedicated حسب وضع العميل.
الفوترة تظل داخل Billing، لكن الوكالة قد تكون reseller أو payer أو support provider.
White-label في V1 هو foundation فقط: logo، portal name، branding fields، وليس multi-tenant agency SaaS كامل.
2. هدف هذا النظام
تمكين وكالة من إدارة عدة مواقع وعملاء من لوحة واحدة.
عرض bulk status overview للمواقع والخطط والصحة والنسخ الاحتياطية والتحديثات.
تسجيل maintenance notes وclient reports لكل موقع أو عميل.
دعوة العميل بصلاحيات محددة دون إعطائه وصولًا كاملًا للوكالة.
ربط خطط الوكالة بالـ Billing وEntitlements وReseller commissions.
تجهيز white-label foundation للبوابة التي يراها العميل.
إتاحة handover من الوكالة إلى العميل إذا انتهت العلاقة.

4. يعتمد على ماذا؟
Core Kernel: users, organizations, organization_memberships, roles, permissions.
Sites / Cloud: sites, cloud_sites, cloud_domains, backups, health checks.
Billing: billing_accounts, plans, subscriptions, entitlements, invoices_platform.
Security: sessions, API tokens, sensitive access logs, audit logs.
Notifications & Inbox: إشعارات للوكالة والعميل وتقارير الحالة.
Teams / Collaboration: اختياريًا لقنوات الدعم والتنبيهات.
Activity/Audit Logs: أي إدارة لموقع عميل أو تغيير صلاحيات يجب تسجيله.
5. Data Domains
Agency Identity: ملف الوكالة ونوعها وحالتها ومجالات خدماتها.
Agency Clients: علاقة الوكالة بالعميل، هل العميل جديد أم Organization موجود.
Client Sites: المواقع التي تديرها الوكالة لكل عميل.
Access & Permissions: منح وصول محدد للوكالة أو للعميل.
Maintenance & Operations: ملاحظات، مراجعات، bulk updates/backups، status snapshots.
White-label Foundation: branding profile وclient portal settings.
Billing & Reseller Links: من يدفع؟ ومن يملك الاشتراك؟ وما عمولة الوكالة؟
Reports & Handover: تقارير العميل وتسليم الإدارة عند انتهاء العلاقة.

31. Agency Dashboard Flow
Agency logs in
→ system checks agency.dashboard.view
→ loads agency_profile
→ loads agency_clients
→ loads agency_client_sites
→ joins site/cloud/billing status
→ shows bulk status overview
→ user opens client site
→ access grant checked
→ action logged in agency_access_logs/activity_logs
32. Add Client Flow
Agency creates client
→ agency_client created
→ optional client_organization created or linked
→ primary contact created/invited
→ client portal created if enabled
→ agency_client_sites added
→ access grants issued
→ notification sent
→ activity logged
33. Client Access Flow
Agency invites client user
→ agency_client_invitation created
→ user accepts invitation
→ organization_membership created if needed
→ agency_client_user_roles assigned
→ agency_client_access_grants created
→ permissions resolved by AccessService
→ every sensitive action logged
34. Bulk Operation Flow
Agency selects many client sites
→ validates permissions per site
→ creates agency_bulk_operation
→ creates agency_bulk_operation_items
→ queued jobs run per item
→ status snapshots update
→ report/notification generated
→ failures stay item-level, not full operation failure
35. Maintenance Report Flow
Monthly schedule or manual request
→ collect site health, backups, updates, notes
→ create agency_client_report draft
→ agency reviews
→ publish to client portal
→ optional export to PDF/DOCX
→ notify report recipients
36. White-label Foundation Flow
Agency enables white-label entitlement
→ agency_branding_profile created
→ logo/name/colors configured
→ agency_client_portal uses branding
→ client sees agency-branded portal
→ Kabeeri ownership/legal footer policy remains configurable by plan
37. Handover Flow
Client or agency requests handover
→ agency_handover_request created
→ permissions and billing checked
→ access grants reviewed
→ client ownership confirmed
→ agency access revoked or reduced
→ billing relationship updated
→ handover completed
→ audit log created

44. علاقة Agency Platform بالأنظمة الخمسة
Mode
سلوك Agency Platform
Cloud
الوضع الأفضل: الوكالة ترى cloud_sites وdomains وbackups وhealth وbilling مباشرة حسب الصلاحيات.
Frontend Anywhere
الوكالة تدير الواجهة الخارجية عبر frontend_projects إذا لديها access grant.
Portable
بعد خروج العميل، علاقة الوكالة يمكن أن تصبح support_only عبر self_hosted_installation status ولا ترى DB العميل إلا بتصريح.
Dedicated
الوكالة قد تدير أو تدعم dedicated tenant، لكن عبر dedicated access policy وليس وصول مباشر دائم.
Core Kernel
كل شيء يبدأ من Organization/User/Membership/Permissions ولا توجد وكالة بدون organization.
45. Security Rules
لا تحصل الوكالة على صلاحيات عامة على كل بيانات العميل لمجرد أنها agency.
كل وصول يجب أن يكون scoped by organization/site/company/resource.
client billing وsecurity logs وprivate documents تحتاج explicit permissions.
client access grants يجب أن تكون قابلة للإلغاء والانتهاء expires_at.
كل bulk operation يجب أن يسجل من طلبها وعلى أي مواقع تمت.
handover يجب أن يراجع access grants والـ billing relationships قبل الإكمال.
White-label لا يجب أن يخفي التزامات Kabeeri القانونية أو الأمنية إذا الخطة تتطلب ظهورها.
46. Privacy & Visibility
ملاحظات agency_internal لا تظهر للعميل.
ملاحظات client_visible تظهر في Client Portal.
تقارير العميل لا تظهر إلا للـ contacts أو users المصرح لهم.
Agency لا ترى Employee evaluations أو payroll أو finance إلا إذا تم منح صلاحيات صريحة من العميل.
Agency access logs يجب أن تكون قابلة للعرض للعميل في الخطط المتقدمة.

49. Acceptance Criteria
Agency Owner يستطيع إنشاء agency profile.
Agency يستطيع إضافة client وربطه بـ organization/site موجود.
Agency dashboard يعرض client organizations وclient sites وsite statuses وplans وmaintenance notes وrecent updates.
Agency يستطيع دعوة العميل بصلاحيات محددة.
Agency يستطيع تسجيل maintenance note visible أو internal.
Bulk status overview يعمل بدون تحميل كل تفاصيل المواقع في كل request.
White-label fields تعمل كبداية: portal name, logo, colors.
كل وصول لموارد العميل يسجل في agency_access_logs أو audit_logs عند الحساسية.
Handover request يمكنه إلغاء أو نقل access grants بأمان.
Billing relationship لا يكرر الفواتير، بل يربط فقط بالـ Billing module.

51. الخلاصة
Agency Platform ليست بديلًا لـ Cloud أو Billing أو Sites، بل طبقة إدارة فوقهم. وظيفتها أن تجعل Kabeeri قابلة للبيع للوكاالت التي تدير عدة مواقع وعملاء، مع الحفاظ على ملكية العميل وصلاحياته، وتسجيل كل وصول أو تغيير. في V1 يكفي أن تدعم dashboard، client sites، access، maintenance notes، bulk status، وwhite-label foundation؛ أما automation المتقدم والـ BI والـ reseller accounting الكامل فيأتي لاحقًا.
