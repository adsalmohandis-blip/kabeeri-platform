هذا الملف يصف تصميم قاعدة البيانات الخاصة بطبقة Kabeeri Mall، وهي السوق الخارجي العام الذي يظهر للجمهور ويعرض الشركات والخدمات والمنتجات والمواهب، مع طبقات ثقة وتوثيق ومراجعة وبلاغات وتقييمات وظهور مميز.
هذا الملف لا يصف Kabeeri Marketplace الداخلي الخاص بالـ plugins/themes/modules. السوق الداخلي له ملف مستقل لاحقًا. هذا الملف يركز على Mall Kabeeri باعتباره شبكة اكتشاف عامة.
1. تعريف Kabeeri Mall
Kabeeri Mall هو السوق الخارجي العام داخل Kabeeri. يستخدمه الزوار والعملاء والشركات والمهنيون لاكتشاف businesses، services، products، talent، وRabet verified companies.
الغرض منه ليس أن يكون مجرد directory، بل طبقة اكتشاف وثقة تربط الموقع والشركة والتوثيق والخدمات والمنتجات والمواهب بواجهة عامة قابلة للبحث والمراجعة والتواصل.
Business Marketplace: ظهور الشركات والبروفايلات التجارية.
Services Marketplace: عرض الخدمات واستقبال الطلبات أو RFQ.
Products Marketplace: عرض منتجات عامة وربطها بمتجر Kabeeri أو رابط خارجي.
Talent Marketplace: ظهور المهنيين حسب إعدادات الخصوصية.
Trust Layer: توثيق Rabet، تقييمات، مراجعات، بلاغات، Moderation، وسجل ثقة.

4. المبادئ الحاكمة
Mall لا يقرأ مباشرة من قاعدة بيانات العميل؛ يستخدم Mall Mirror أو Mall Listing Index.
أي نشر عام يحتاج publication consent واضح.
أي تحديث من Portable أو Dedicated يدخل عبر Mall Sync API ثم moderation/trust checks.
البيانات الخاصة لا تنتقل إلى Mall: orders private، invoices، accounting، payroll، internal messages، private contracts، supplier costs.
Verified لا تعني أن كل بيانات الشركة صحيحة للأبد؛ يجب دعم verification_level وexpiry وtrust_status.
Moderation يغلب Source. حتى لو أرسل المصدر تحديثًا، يستطيع moderator إخفاء أو تعليق العنصر.
Featured/Sponsored يجب أن تكون طبقة منفصلة عن الثقة، ولا يجب أن تبدو كتوثيق.
V4 يبدأ بـ contact/request actions وcatalog؛ لا يبدأ بـ full multi-vendor checkout.

21. Flows
21.1 نشر Business Profile في Mall
Business owner requests Mall publication
→ check permission mall.business.publish
→ check mall_publication_consent
→ create/update mall_mirror_businesses
→ create/update mall_listings type=business
→ moderation status = pending
→ moderator approves
→ publication_status = published
→ search index updated
→ activity/audit log recorded
21.2 نشر Product من Commerce إلى Mall
Product marked as public and mall_enabled
→ check consent products_publication
→ copy only public fields to mall_mirror_products
→ create mall_listing type=product
→ exclude private cost, supplier data, margins, internal stock details
→ moderation/trust checks
→ index listing
→ visitor can view product or click external/store URL
21.3 تحديث من Portable أو Dedicated
External instance fires ProductUpdated
→ signed payload sent to Mall Sync API
→ validate token and source status
→ validate allowed public fields
→ create mall_sync_event
→ update mirror table
→ moderation may hold or approve change
→ listing index updated
→ public Mall displays latest approved mirror
21.4 بلاغ ومراجعة
Visitor reports listing or review
→ mall_report created
→ if high risk open moderation case
→ moderator reviews content and trust context
→ action is recorded
→ listing/review status changes
→ affected owner notified
→ appeal may be allowed later
21.5 Featured Listing
Business requests featured placement
→ entitlement/billing check
→ campaign created
→ moderation status must be clean
→ featured listing scheduled
→ public UI shows label Featured/Sponsored
→ impressions/clicks tracked
→ campaign expires automatically

Private product fields are not copied to Mall mirror.

Moderation suspended listing is hidden even if source sends published.
Review requires moderation when flagged.

31. Release Gate
Business يمكن أن يظهر في Mall بعد consent وmoderation.
Service/Product يمكن نشرهما كبيانات عامة بدون كشف بيانات خاصة.
Mall public pages تعمل: /mall, /mall/businesses, /mall/services, /mall/products, /mall/talent.
Search/filter basic يعمل بالتصنيف والدولة والمدينة والنوع.
Review basic يعمل مع moderation/reporting.
Featured listing يظهر مع label واضح ولا يخلط مع verification.
Portable/Dedicated sync لا يتجاوز moderation.
No critical privacy leak في Mall mirror أو listing payloads.
Activity/Audit logs موجودة لكل إجراء حساس.
Permissions وfeature flags تغلق كل أجزاء Mall عند الحاجة.
32. ملخص القرار
Kabeeri Mall يجب أن يبنى كطبقة عامة مستقلة تعتمد على Mall Mirror وPublication Consent، وليس كنافذة مباشرة على بيانات العميل. هذا التصميم يسمح بأن يبدأ العميل Cloud، ثم ينتقل إلى Frontend Anywhere أو Portable أو Dedicated بدون فقد ظهوره العام، مع الحفاظ على الخصوصية والثقة والحوكمة.
في V4، الهدف هو Mall V1: businesses، services، products basic، reviews basic، contact/request actions، featured listings foundation، moderation queue، reports/flags. أما commissions وmulti-vendor checkout وadvanced disputes فتنتقل إلى V5/V6.
