Kabeeri Security & Compliance Database
نظام قاعدة بيانات الأمن والامتثال وحماية البيانات
هذا الملف يصف قاعدة بيانات طبقة الأمن والامتثال في KABEERI، وهي طبقة عرضية تخدم Core Kernel وCloud وFrontend Anywhere وPortable وDedicated وCMS وCommerce وERP وRabet وMall وAI وIntegration Hub.
القاعدة: الأمن ليس Feature منفصلة، بل جزء من Core. أي كيان أو موديول جديد يجب أن يجيب: ماذا يقرأ؟ ماذا يكتب؟ ما الصلاحيات؟ هل يحتاج Audit؟ هل يحتوي بيانات حساسة؟ هل يحتاج موافقة؟ وهل يمكن التراجع عنه؟
1. هدف ملف Security & Compliance Database
الهدف هو تثبيت طبقة بيانات مركزية للأمن والامتثال قبل تضخم المنصة، بحيث لا يتم بناء الفواتير أو ERP أو AI أو Marketplace أو Legal Verification بدون تتبع أمني وخصوصية وموافقات واضحة.
تسجيل الدخول والجلسات ومحاولات الدخول ومخاطر الحسابات.
إدارة MFA والسياسات الأمنية للأدوار الحساسة.
تسجيل Security Events وSensitive Access Logs وAdmin Actions.
إدارة API Tokens وWebhook security وscopes وrevocation.
تصنيف البيانات: public, internal, confidential, restricted.
حفظ سجلات الخصوصية: consent, data export, deletion, retention.
إدارة الحوادث الأمنية: detect, triage, contain, investigate, notify, fix, review.
دعم V4 Security Center ثم V6 Enterprise Security وGRC وSIEM وPrivileged Access.

3. مبادئ التصميم
Security by Design: كل جدول حساس يبدأ بفكرة التصنيف والصلاحيات والتسجيل.
Privacy by Design: لا يتم نشر أو مزامنة بيانات عامة بدون Consent واضح.
Audit by Default: التغيير الحساس والقراءة الحساسة يجب أن يتركا أثرًا.
Least Privilege: API token أو package أو AI skill يحصل فقط على أقل scopes لازمة.
Deny Overrides Allow: أي override بالمنع يغلب السماح.
No Plain Secrets: لا نحفظ password أو API key أو OAuth token كنص واضح.
Human Approval for Risk: الإجراءات الحساسة تحتاج موافقة أو re-authentication أو MFA.

5. Data Classification Model
يجب أن يحمل كل كيان حساس تصنيفًا مباشرًا أو مشتقًا. التصنيف لا يخص التخزين فقط، بل يتحكم في الظهور، التصدير، السجلات، الإرسال إلى AI، والمزامنة مع Mall.

7. Security Flows
7.1 Login + MFA Flow
User submits login→ validate credentials→ create login_attempt→ calculate risk score→ if MFA required: challenge→ if success: create user_session→ create security_event→ show session in Security Center
7.2 Sensitive Access Flow
User requests restricted object→ Permission check→ Data classification check→ Re-auth / MFA if required→ Capture reason if policy requires→ create sensitive_access_logs→ return object or deny
7.3 API Token Flow
User creates API token→ choose scopes→ check risky scopes→ generate token once→ store token_hash only→ log security_event ApiTokenCreated→ every request validates hash + scope + expiry + revocation→ usage recorded→ token can be revoked immediately
7.4 Webhook Security Flow
Event generated→ payload built→ payload_hash calculated→ signature with webhook secret→ delivery created→ retry on failure→ log response excerpt only→ rotate secret if compromised
7.5 Privacy Data Request Flow
User submits data request→ verify identity→ create data_subject_request→ determine modules affected→ collect request items→ export/delete/anonymize according to policy→ retention_holds checked→ complete request→ audit log created
7.6 Incident Management Flow
Detect→ create incident_report→ Triage→ Contain→ Investigate→ Notify affected parties if needed→ Fix→ Post-incident review→ Improve controls
7.7 Privileged Support Access Flow
Support requests access→ customer/platform security admin approves→ temporary scoped access granted→ all actions create admin_action_logs and sensitive_access_logs→ access expires automatically→ report generated

12. العلاقة مع الأنظمة الخمسة
النظام
قواعد الأمن والامتثال
Core Kernel
RBAC, audit_logs, activity_logs, users, memberships هي الأساس. هذا الملف يضيف طبقات security events وMFA وprivacy.
Kabeeri Cloud
Security Center يظهر الجلسات، MFA، API tokens، backups، package risk، admin actions.
Frontend Anywhere
API keys scoped، CORS/allowed origins، rate limiting، public data contract، لا وصول للداتا الخاصة.
Kabeeri Portable
Export يجب أن يسجل، tokens للمزامنة hashed، لا تصدير platform secrets، retention policy بعد الخروج.
Kabeeri Dedicated
Privileged support access، dedicated health/security reports، SIEM، SSO، isolated backups.

16. أخطاء ممنوعة
بناء النظام بدون RBAC من البداية.
حفظ API keys أو OAuth tokens أو payment credentials كنص واضح.
جعل الملفات القانونية أو payroll public أو على public disk.
السماح للـ AI برؤية كل شيء أو تنفيذ تغييرات حساسة بدون approval.
السماح للـ plugins/packages بصلاحيات واسعة بدون manifest وpermission disclosure.
بناء Billing أو ERP أو Finance بدون audit traceability.
ترك Platform Admin بدون reason field وadmin action log.
تجاهل retention/legal holds أثناء deletion أو export.
Webhook بدون signature/timestamp/replay protection.
17. Definition of Done
Security Center يعرض MFA status وactive sessions وAPI tokens وrecent events وsensitive logs.
MFA يعمل ويمكن فرضه على platform/legal/security roles.
كل API token له scopes وhash وlast_used وrevocation.
