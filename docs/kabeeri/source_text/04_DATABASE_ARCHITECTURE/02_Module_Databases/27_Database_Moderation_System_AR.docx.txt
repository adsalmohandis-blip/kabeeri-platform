KABEERI Database File 27 — Moderation System Database
نظام الإشراف والمراجعة على المحتوى العام داخل Kabeeri
هذا الملف يصف تصميم قاعدة البيانات الخاصة بطبقة Moderation System، وهي طبقة مركزية تحمي Kabeeri Mall وTalent Marketplace وReviews وMessages وPublic Listings من المحتوى المخالف أو المضلل أو الخطر.
1. تعريف Moderation System
Moderation System هو النظام المسؤول عن استقبال البلاغات، مراجعة المحتوى العام، تطبيق قرارات الإخفاء أو التعليق أو الرفض، وإدارة الاعتراضات والتصعيد. لا يمثل هذا النظام مصدر الحقيقة للمحتوى، بل يتحكم في قابلية ظهوره للعامة.
• يحمي Kabeeri Mall من الشركات المزيفة، الخدمات الوهمية، المنتجات المخالفة، والتقييمات المصطنعة.
• يحمي Talent Marketplace من الملفات المهنية المضللة أو الرسائل المسيئة.
• يحمي Reviews/Reputation من التلاعب والتشهير والسبام.
• يحمي المنصة من نشر بيانات خاصة أو قانونية أو مالية داخل واجهات عامة.
2. لماذا هذا الملف مهم؟
أي سوق عام بدون Moderation سيتحول سريعًا إلى مصدر مخاطر: احتيال، محتوى مخالف، إساءة، تسريب بيانات، تلاعب في السمعة، وانخفاض الثقة. لذلك يجب أن تكون moderation foundation جاهزة قبل إطلاق Mall أو Talent بشكل عام.
3. ما الذي يحتاج Moderation؟
• Business profiles.
• Services.
• Products.
• Professional profiles.
• Reviews.
• Messages.
• Images and media.
• Public descriptions.
• Marketplace listings.
• Package submissions لاحقًا في Developer Marketplace.
4. المبادئ الحاكمة
المبدأ
المعنى
Public-first protection
أي شيء يظهر للعامة يجب أن يكون قابلًا للمراجعة أو البلاغ أو الإيقاف.
Mirror-safe moderation
Kabeeri Mall لا يقرأ مباشرة من قاعدة العميل؛ بل يراجع ويعرض Mall Mirror فقط.
Deny beats publish
إذا وُجد قرار suspension أو rejection فلا يظهر المحتوى حتى لو المصدر يقول published.
Human decision for high risk
القرارات عالية الخطورة لا تعتمد على AI وحده، بل تحتاج Moderator أو Workflow Approval.
Audit everything
كل قرار مهم يجب أن يسجل: من قرر؟ متى؟ لماذا؟ وعلى أي كيان؟
Appeal available
يجب أن توجد آلية اعتراض للقرارات المؤثرة مثل suspension أو removal.
5. حدود الملف
هذا الملف لا يبني Mall كامل ولا Reviews كامل ولا Disputes كامل؛ بل يحدد طبقة الإشراف التي تتكامل معهم. جداول Reviews وDisputes وMall Mirror تبقى في ملفاتها، بينما هذا الملف يحدد البلاغات، queue، المراجعات، الأفعال، القرارات، والاعتراضات.

25. Flows
25.1 Pre-publish Moderation Flow
User submits public listing → publication_status = pending_review → moderation_case created → queue item assigned → moderator reviews → decision issued → content published/needs_changes/rejected.
25.2 User Report Flow
Visitor reports review/product/service → moderation_report created → existing case checked → queue item created → moderator reviews → action applied → reporter/owner notified.
25.3 Automated Flag Flow
Content saved/published → rules engine scans → rule match created → if high risk: block/queue → if low risk: flag only → moderator confirms or dismisses.
25.4 Appeal Flow
Owner receives decision → submits appeal → second moderator reviews → accept/reject/partial → actions reversed or confirmed → audit log updated.
25.5 Mall Mirror Flow
Source updates public data → Mall Mirror updates as draft/pending → moderation checks → only approved/published appears publicly.
25.6 Portable/Dedicated Flow
External instance sends signed public update → validate sync source → create moderation_sync_event → apply rules → update mirror only after policy check.

29. Notifications
• Notify owner when content enters pending_review إذا كان التأخير متوقعًا.
• Notify owner when decision requires changes or content is suspended.
• Notify reporter only with safe generic outcome: reviewed/closed/action_taken، بدون كشف بيانات داخلية.
• Notify senior moderator when SLA is breached أو risk_level critical.
30. AI Assistance Rules
يمكن للـ AI أن يقترح risk score أو يشرح سبب flag أو يلخص أدلة case، لكنه لا يطبق قرارًا عالي الخطورة وحده. كل AI suggestion يجب أن يسجل في audit logs، وأي action مثل suspend/remove يحتاج human approval.

31. Frontend Anywhere Rules
في Frontend Anywhere مصدر البيانات داخل Kabeeri Cloud، لذلك moderation تعمل داخليًا قبل تحديث Mall Mirror أو snapshots. الواجهة الخارجية لا تستطيع bypass moderation لأنها لا تملك قاعدة البيانات ولا admin logic.
32. Portable Rules
في Portable قد يرسل العميل public updates إلى Mall Sync API. هذه التحديثات لا تنشر مباشرة؛ بل تمر عبر validation + moderation rules + consent check. إذا تم suspension داخل Kabeeri Central، يجب أن يغلب على أي حالة published قادمة من النسخة الخارجية.
33. Dedicated Rules
في Dedicated يتم تطبيق نفس schema داخل بيئة العميل حسب الحاجة، لكن قرارات الظهور العام في Kabeeri Mall تظل داخل Central Mall Mirror. Dedicated لا يتصل مباشرة بجداول Mall، بل عبر Sync API ومفاتيح موقعة.
34. Retention & Privacy
• بلاغات الإساءة والاحتيال تحفظ مدة أطول إذا أثرت على الثقة أو النزاعات.
• بلاغات false positive يمكن إخفاء تفاصيلها من التقارير العامة.
• يجب عدم إظهار هوية reporter للمالك إلا إذا كانت السياسة تسمح.
• المرفقات الحساسة تستخدم Media/DMS permissions ولا تظهر كمرفقات عامة.

38. Tests
• Unauthorized user cannot see moderation queue.
• Reporter can submit report but cannot see internal notes.
• Suspended listing does not appear in Mall public search.
• Published source update from Portable cannot override central suspension.
• Senior-only action remove/suspend requires correct permission.
• Appeal can reverse action and restore publication_status.
• Rule match opens queue item for high-risk content.
• Audit log is created for every decision and action.
39. Acceptance Criteria
• كل كيان عام يمكن وضعه في pending_review أو suspended أو rejected.
• يمكن إنشاء report لأي listing/review/profile/message عام.
• يوجد moderation queue قابل للتصفية حسب type/risk/priority/status.
• كل action حساس مسجل في audit log.
• Mall لا يعرض محتوى مرفوض أو معلق حتى لو source status = published.
• يمكن تقديم appeal للقرارات المؤثرة.
• Portable/Dedicated sync لا يتجاوز consent أو moderation.
40. ملخص تنفيذي
Moderation System هو صمام أمان Kabeeri Mall وTalent وReviews. لا يجب إطلاق سوق عام أو محتوى قابل للبلاغ بدون هذه الطبقة. البداية تكون بسيطة: status foundation + reports + queue + actions، ثم تتوسع إلى rules وSLA وappeals وtrust impacts وAI assist. القاعدة الحاكمة: لا ظهور عام بدون visibility + consent + moderation-ready state.
