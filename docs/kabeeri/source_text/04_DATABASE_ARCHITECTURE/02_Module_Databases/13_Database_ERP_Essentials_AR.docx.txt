1. تعريف ERP Essentials
ERP Essentials هو الحد الأدنى العملي من أنظمة التشغيل الداخلية التي تحتاجها الشركة بعد أن يصبح لديها موقع أو متجر أو طلبات خدمات. لا يبدأ Kabeeri كنظام ERP ثقيل، بل يبدأ من الموقع والمتجر ثم يضيف التشغيل تدريجيًا.
تحويل Service Requests وForm Submissions إلى Leads.
إدارة العملاء وجهات الاتصال وخط مبيعات بسيط.
إنشاء عروض أسعار وتحويلها إلى فواتير.
ربط المنتجات والطلبات بالمخزون.
إدارة الموردين وأوامر الشراء الأساسية.
تأسيس محاسبة بداية بدون ادعاء أنها محاسبة كاملة.
إدارة ملفات موظفين وتقييمات خاصة.
تشغيل موافقات بسيطة على الإجراءات الحساسة.
إنتاج تقارير تشغيلية أساسية.

4. قواعد تصميم قاعدة البيانات
كل جدول تشغيلي يجب أن يحتوي organization_id على الأقل، وعند الحاجة company_id وsite_id.
لا نخلط فواتير Kabeeri Platform Billing مع فواتير العميل لعملائه. فواتير العميل تستخدم جداول customer_invoices.
العمليات الحساسة مثل posting journal أو stock adjustment أو invoice issue تسجل في audit_logs.
أي كيان قابل للتصدير يجب أن يستخدم uuid بجانب id الداخلي.
Accounting Starter لا يحاول تغطية كل المحاسبة، لكنه يضع الأساس للربط مع V5 Accounting Pro.
Inventory movements هي مصدر الحقيقة لحركات المخزون، وليس stock_balances وحدها.
Employee evaluations private by default ولا تظهر في Talent Marketplace.

19. Flows تشغيلية
19.1 Service Request إلى Lead
Visitor submits service request → service_request created → crm_lead created with source_type=service_request → assigned_to sales user → crm_customer_timeline event → notification sent.
19.2 Lead إلى Quotation إلى Invoice
Sales user qualifies lead → quotation draft → optional approval → quotation sent → customer accepts → customer_invoice created → quotation status converted → timeline updated.
19.3 Order إلى Stock Reservation إلى Invoice
Commerce order confirmed → stock_reservations created → stock_movements reservation/out after fulfillment → customer_invoice optional → payment recorded → invoice balance updated.
19.4 Purchase Order إلى Stock Receipt
Purchasing user creates PO → approval request if threshold applies → PO approved → goods received → purchase_receipt posted → stock_movements in → stock_balances updated.
19.5 Accounting Starter Posting
Invoice issued or payment recorded → optional journal draft generated → accountant reviews → journal_entry posted → audit log created. في V3 يمكن جعل journal generation manual أو semi-automatic فقط.
19.6 Employee Evaluation
Manager opens evaluation form → employee_evaluation draft → answers saved → submitted → HR/manager review → locked. لا تظهر البيانات في Talent Marketplace ولا Mall.

21. Frontend Anywhere Rules
Frontend Anywhere لا يحصل على API لقراءة ERP private data.
يمكن فقط عرض public catalog أو service request endpoints حسب scopes.
Leads الناتجة من forms الخارجية تسجل داخل Cloud DB.
Invoices, employees, accounting, purchasing, evaluations ممنوعة من public API.
أي API لإرسال request أو form يجب أن يستخدم scoped key وrate limiting وCORS allowed origins.
22. Portable Rules
كل جداول ERP Essentials يجب أن تسجل نفسها في Tenant Export Registry.
يجب الحفاظ على uuid للكيانات التي قد تتزامن لاحقًا مع Mall أو Cloud import.
Accounting/audit logs قد تحتاج retention policy حسب الاتفاق.
Employee evaluations والملفات الخاصة لا تصدر إلا إذا include_private_files وpolicy تسمح.
بعد Portable، Mall Sync لا يرسل ERP private data إطلاقًا.
23. Dedicated Rules
Dedicated يستخدم نفس schema للـ ERP Essentials داخل قاعدة العميل المخصصة.
organization_id يظل موجودًا حتى لو العميل واحد لتوحيد الكود ودعم multi-company.
Central Kabeeri قد يستقبل usage summaries فقط، وليس تفاصيل ERP.
support access لأي بيانات ERP يحتاج approval مؤقت وتسجيل audit.
health reports لا تشمل بيانات العملاء أو الفواتير التفصيلية.

27. Acceptance Criteria
يمكن تحويل Service Request إلى Lead بدون فقد المصدر.
يمكن إنشاء Quotation وتحويله إلى Customer Invoice.
يمكن إصدار Invoice وتسجيل Payment وتحديث balance_due.
يمكن ربط Product بـ Stock Item وتحديث Stock Balance عبر Movement.
يمكن إنشاء Purchase Order واستلامه وتوليد Stock Movement.
يمكن إنشاء Journal Entry draft وترحيله بصلاحية منفصلة.
لا يستطيع مستخدم بدون صلاحية رؤية employee evaluations.
تسجل audit logs للأفعال الحساسة: invoice issue, stock adjustment, journal posting, evaluation review.
تعمل feature flags لتعطيل أي suite بدون كسر باقي النظام.
تسجل جداول ERP Essentials في Export Registry لدعم Portable لاحقًا.
28. ملاحظات تنفيذ Laravel
استخدم Models منفصلة لكل domain مع Policies واضحة.
لا تضع منطق إصدار الفاتورة داخل Controller؛ استخدم Action مثل IssueCustomerInvoiceAction.
حركات المخزون يجب أن تمر عبر StockMovementService لمنع تعديل stock_balances مباشرة.
journal posting يجب أن يكون transaction آمنًا ويتحقق من توازن debit/credit.
استخدم Observers أو Events لتسجيل activity_logs، لكن audit_logs الحساسة يجب أن تكون explicit.
استخدم Form Requests للتحقق من إدخالات quotations/invoices/purchase orders.
كل تحويل مثل quotation_to_invoice يجب أن يكون idempotent قدر الإمكان.
29. الخلاصة
هذا الملف يضع قاعدة بيانات ERP Essentials كطبقة تشغيل أولية فوق Kabeeri Core وCommerce وRabet. الهدف ليس بناء ERP كامل في V3، بل ربط البيانات الأساسية بطريقة صحيحة تمنع إعادة البناء لاحقًا. بعد هذا الملف يمكن التوسع إلى ERP Pro في V5 بدون كسر نماذج العملاء، الفواتير، المخزون، المشتريات، الموظفين، والموافقات.
