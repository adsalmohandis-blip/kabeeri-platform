1. الهدف
الهدف هو بناء Event-driven Modular Monolith بحيث تتكامل الموديولات عبر Events وListeners وWorkflows وWebhooks بدل الاستدعاءات المباشرة العشوائية.

3. Event Shape
• event_key مثل ContentPublished أو OrderPaid.
• organization_id / company_id / site_id عند الحاجة.
• actor_user_id إن وجد.
• subject_type وsubject_id.
• payload_hash لتتبع التغييرات بدون الاعتماد على payload كبير.
• risk_level لتوجيه audit/approval.
4. Workflows
Workflow يملك definition وversion، وكل تشغيل workflow_run يرتبط بكيان مثل quotation أو purchase request أو verification request أو AI change plan.
5. Approval Rules
• أي approval له requester، approver، status، SLA، comments، وaudit log.
• deny أو rejection يسجل السبب ولا يحذف الطلب.
• AI sensitive changes يجب أن تستخدم approval_requests قبل apply.
6. Flows
• ContentPublished → clear cache → update sitemap → notify editors → log activity.
• OrderPaid → create invoice → reserve/deduct stock → notify customer → trigger accounting later.
• CompanyVerified → update trust record → update Mall mirror → notify owner.
• AIPlanApproved → create rollback point → apply changes → audit log.
7. قواعد الأمان
• No listener may bypass permissions.
• No workflow applies sensitive action without explicit approval.
• Failed listeners do not lose event history.
• Webhooks use signed payloads and retry limits.
