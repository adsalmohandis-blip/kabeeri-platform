1. هدف قاعدة بيانات Localization & Country Packs
Kabeeri ليست CMS فقط، بل تحتوي CMS وCommerce وERP وRabet Verification وKabeeri Mall وTalent وBilling وPayroll وTax وE-invoicing وPayments وShipping. لذلك اختلاف الدولة لا يؤثر على النصوص فقط، بل يؤثر على طريقة تشغيل النظام بالكامل.
هدف هذا الملف هو بناء طبقة بيانات مستقلة تسمح بتفعيل قواعد دولة معينة على Organization أو Company أو Site أو Module بدون إعادة بناء النظام أو تعديل Core.
دعم اللغة والعملة وتنسيقات التاريخ والأرقام والعناوين والهواتف.
دعم قواعد الضرائب والفواتير والفاتورة الإلكترونية حسب الدولة.
دعم متطلبات Rabet Legal Verification حسب الدولة ونوع الشركة والنشاط.
دعم بوابات الدفع وشركات الشحن المحلية بدون تفعيل غير صحيح في دولة غير مدعومة.
تجهيز Payroll وEmployment Rules كأساس مؤجل لا يفعل بدون مراجعة قانونية محلية.
تسهيل تحديث الحزم عند تغير القوانين مع Impact Analysis وActivity/Audit Logs.
2. المبادئ الحاكمة
المبدأ
الشرح
No Country Logic in Core
لا تكتب قواعد الضرائب أو التوثيق أو الرواتب داخل Core. Core يستدعي Country Pack Services.
Versioned Packs
كل Country Pack له نسخة وسريان effective_from/effective_to حتى يمكن تتبع التغييرات القانونية.
Scoped Activation
تفعيل الحزمة قد يكون على مستوى Organization أو Company أو Site أو Billing Account أو Module.
Legal Review Required
أي حزمة تحتوي tax/payroll/legal/e-invoicing يجب أن تمر بمراجعة قانونية أو ضريبية محلية.
Module-aware Rules
القواعد ليست عامة فقط؛ قد تطبق على Commerce أو ERP أو Rabet أو Payroll أو Billing.
Safe Updates
تحديث الحزمة لا يطبق تلقائيا على بيانات حساسة بدون تحليل أثر وموافقة عند الحاجة.
Portable/Dedicated Ready
كل قواعد الدولة يجب أن تكون قابلة للتصدير أو المزامنة مع Portable/Dedicated حسب الترخيص.

15.3 Country Pack Update Flow
New country_pack_version is created.
Legal/Tax/Compliance review is completed if needed.
Impact analysis runs for affected organizations and modules.
User/admin sees affected modules and risky changes.
Approval is requested for high-risk changes.
Update applies rules in safe order.
Activity log and audit log are created.
Affected invoices/tax/verification settings are validated.

16.2 Activation Flow
Organization selects country→ system finds active Country Pack→ plan/entitlement check→ install country_pack_installation→ apply organization/company/site localization settings→ enable tax/invoice/payment/shipping/verification components→ create activity log→ run validation report
16.3 Invoice Flow
Invoice draft created→ resolve company country pack→ load invoice_rules + tax_calculation_profile→ calculate taxes→ assign invoice_numbering_sequence→ validate required fields→ generate PDF/HTML template→ if e-invoicing enabled, create e_invoice_submission→ log audit event
16.4 Verification Flow
Company selects registered country + company type→ load country_company_types→ load country_verification_document_rules→ show required documents→ company uploads documents→ assign legal partner authorized for country/activity→ reviewer follows checklist→ verification result updates trust record
16.5 Payment/Shipping Flow
Checkout starts→ resolve site/company country pack→ load payment_gateway_country_rules→ filter unsupported gateways→ load shipping_provider_country_rules + shipping_zone_rules→ show only available methods→ order stores country_pack_version used for traceability

20. الخلاصة التنفيذية
ملف Localization & Country Packs Database يحول التوطين من ترجمة واجهة إلى طبقة تشغيل كاملة. هذه الطبقة تحدد كيف تعمل Kabeeri قانونيا وماليا وتشغيليا في كل دولة، بدون كسر Core أو إعادة بناء النظام لكل سوق.
القاعدة النهائية: Country Pack هو عقد تشغيل محلي بين Core وModules. كل دولة لها قواعدها، وكل قاعدة لها نسخة وسريان ومراجعة وأثر وسجل.
