هذا الملف يصف تصميم قاعدة البيانات الخاص بـ Talent Marketplace، وهو الجزء الذي يسمح للأفراد بإنشاء ملفات مهنية عامة أو خاصة، وإدارة المهارات والخبرات والتوفر، واستقبال عروض عمل أو تعاون من الشركات، مع حماية الخصوصية وفصل بيانات الموارد البشرية الداخلية عن الظهور العام.
الهدف ليس بناء منصة freelancing عشوائية، بل بناء طبقة Workforce Network موثوقة داخل Kabeeri، مرتبطة بـ Users وCompanies وMemberships وRabet وMall وTeams وContracts لاحقًا.
1. تعريف Talent Marketplace
Talent Marketplace هو سوق مواهب داخل Kabeeri Mall يسمح بظهور المستخدم كمحترف مستقل أو موظف سابق/حالي له ملف مهني قابل للتحكم في خصوصيته. الملف المهني ليس هو حساب المستخدم، وليس سجل الموظف الداخلي، وليس عضوية الشركة، بل واجهة مهنية اختيارية قابلة للنشر أو الإخفاء.
User = الشخص الحقيقي الذي يدخل النظام.
Professional Profile = الواجهة المهنية الاختيارية لهذا الشخص.
Company Membership = علاقة المستخدم بشركة معينة كموظف أو متعاقد أو مستشار.
Employee Profile = ملف HR داخلي داخل الشركة، لا يظهر في السوق العام.
Talent Listing = نسخة عامة أو مفهرسة من Professional Profile داخل Mall/Talent Search.
2. هدف النظام
تمكين المستخدم من عرض نفسه كمحترف مع تحكم كامل في visibility.
تمكين الشركات الموثقة أو المصرح لها من إرسال عروض عمل أو تعاون.
ربط المهارات والخبرات وسجل العمل بعلاقات Kabeeri الداخلية بدون كشف بيانات حساسة.
دعم privacy-first public profile بحيث لا تظهر التقييمات أو البيانات الداخلية إلا بموافقة واضحة.
التمهيد لـ V5/V6: reputation scoring، contracts، HR integration، AI talent matching، وworkforce analytics.
3. حدود النظام — ما هو وما ليس
3.1 ما هو Talent Marketplace
ملفات مهنية عامة/خاصة.
مهارات وخبرات ومحفظة أعمال.
إعدادات ظهور وتوفر واستقبال عروض.
عروض عمل أو تعاون basic.
مراسلة company-to-professional foundation.
سمعة وتقييمات مهنية عامة بحذر.
ربط لاحق بالعقود والعضويات والمهام.
3.2 ما ليس Talent Marketplace في V4
ليس HR كاملًا.
ليس Payroll.
ليس recruiting suite كاملًا.
ليس freelance escrow platform.
ليس تقييم أداء داخلي عام.
ليس بديلًا عن Contracts/CLM في V5.
ليس AI matching كاملًا قبل V6.
4. الاعتماديات الأساسية
لا يبدأ Talent Marketplace قبل وجود Core وMemberships وPrivacy وModeration foundation، لأن البيانات المهنية حساسة ويمكن أن ترتبط بشركات متعددة وسجل عمل وتقييمات.

5. Data Domains
Professional Identity: الملف المهني، العنوان، النبذة، الصورة، الحالة.
Skills Graph: المهارات، مستوياتها، سنوات الخبرة، endorsements.
Work History: تاريخ عمل موثق أو غير موثق مع تحكم في الظهور.
Portfolio: أعمال عامة أو روابط أو ملفات مختارة.
Availability & Preferences: التوفر، نوع العمل المطلوب، الموقع، الراتب المتوقع اختياريًا.
Job Offers: عروض العمل والتفاوض والقبول/الرفض.
Reputation: تقييمات عامة، endorsements، trust signals، وليس تقييمات HR الخاصة.
Privacy & Consent: الموافقات، visibility، opt-in/out، logs.
Moderation: بلاغات، إخفاء، تعليق، review queue.
Mall Mirror: نسخة عامة للبحث والاكتشاف.

29. Talent Mall Mirror
الظهور في Kabeeri Mall أو نتائج البحث العامة لا يجب أن يقرأ professional_profiles مباشرة في كل حالة. الأفضل وجود نسخة عامة mirror مثل mall_mirror_talent أو talent_public_index، يتم تحديثها فقط من بيانات وافق المستخدم على نشرها.
mall_mirror_talentiduuiduser_id nullableprofessional_profile_id nullablemall_sync_source_id nullableexternal_id nullableheadline nullablesummary nullableskills json nullablecountry_id nullablecity nullableavailability_status nullablevisibility default hiddensource_status default activepublication_status default draftlast_synced_at nullablemetadata json nullablecreated_atupdated_at
Mirror لا يحتوي على private notes أو salary preferences الخاصة أو evaluations الداخلية.
أي revoke consent يجب أن يحدث mirror إلى hidden/disconnected أو يحذف البيانات العامة حسب السياسة.

31. Flows
31.1 إنشاء ملف مهني
User opens Personal Space→ create professional_profile draft→ add headline/summary/skills→ configure visibility settings→ grant or deny publication consents→ preview public profile→ submit/publish→ optional moderation→ update mall_mirror_talent if allowed
31.2 إرسال عرض عمل
Company user searches Talent→ checks permission job_offer.send→ checks professional allows offers→ create job_offer draft→ add job_offer_terms→ send offer→ notify professional→ professional views/accepts/rejects/negotiates→ status history recorded→ optional contract or company_membership workflow later
31.3 تحويل قبول العرض إلى عضوية شركة
JobOffer accepted→ optional Contract generated→ company admin approval→ create company_membership→ assign role→ onboarding tasks created→ professional_work_history can be linked later with consent
31.4 إخفاء سجل عمل
Professional changes work history visibility→ update professional_work_history.visibility→ create talent_privacy_event→ refresh mall_mirror_talent→ remove public references if needed

33. Privacy Rules
Professional Profile لا يظهر للعامة افتراضيًا. الوضع الافتراضي private.
Work History لا يظهر إلا إذا visibility تسمح بذلك، حتى لو كان مرتبطًا بـ company_membership.
Employee evaluations الخاصة لا تنسخ إلى professional_reviews.
Salary/rate preferences لا تظهر إلا إذا اختار المستخدم ذلك.
الشركة لا ترى بيانات اتصال مباشرة إلا إذا public_contact_enabled أو عبر messaging/inquiry flow.
أي شركة محظورة من المستخدم لا تستطيع إرسال inquiry أو job offer.
Mall indexing يحتاج consent منفصل عن profile publication.
34. Moderation & Trust Rules
أي profile public يمكن التبليغ عنه.
fake work history يتحول إلى talent_moderation_case وربما work_history_verification.
reviews العامة قابلة للاعتراض ولا تظهر مباشرة في الحالات الحساسة.
verification_status لا يعني أن الشخص موظف حاليًا؛ فقط أن هوية أو خبرة معينة تم التحقق منها.
moderation يمكنها override publication_status بدون تغيير source data.
35. Frontend Anywhere
الواجهة الخارجية تقرأ فقط public talent mirror أو public API scopes.
لا تسمح API العامة بقراءة private work history أو job offers.
إرسال inquiry من frontend خارجي يحتاج scope محدد وrate limit.
أي تغيير في visibility يؤدي إلى cache invalidation للواجهة الخارجية.
36. Portable
Professional Profile الخاص بالعميل لا يصدر إلا إذا كان المستخدم ضمن organization data أو وافق على ذلك حسب السياسة.
job_offers المرتبطة بالمنظمة يمكن تصديرها كبيانات تشغيلية للعميل، لكن بيانات المستخدم الشخصية غير التابعة قد تحتاج anonymization.
إذا استمر Mall Sync بعد الخروج، يرسل Portable فقط public talent payload بموافقة المستخدم.
UUIDs يجب أن تبقى ثابتة للمزامنة مع Mall Mirror.
37. Dedicated
في Dedicated يمكن بقاء professional_profiles داخل Dedicated DB إذا كانت جزءًا من tenant.
Mall Central لا يقرأ Dedicated DB مباشرة، بل عبر sync API.
Enterprise customers قد يحتاجون policy تمنع نشر talent خارج بيئتهم إلا بموافقة المؤسسة والمستخدم.

39. Indexing & Search
البحث العام يستخدم talent public index أو mall_mirror_talent لاستخدام أسرع وآمن.
الفلاتر الأساسية: category, skills, country/city, availability, verification status, rating, remote preference.
لا يدخل private metadata في search index.
عند revoke consent يجب حذف/إخفاء السجل من index بسرعة.

41. Testing Priorities
مستخدم لا يستطيع نشر profile شخص آخر.
الشركة لا تستطيع إرسال job_offer إذا المحترف أغلق استقبال العروض.
work_history private لا يظهر في public API ولا Mall Mirror.
revoking consent يخفي profile من index.
قبول job offer لا ينشئ company_membership بدون approval.
reviews الداخلية لا تظهر كـ public reviews.
moderator يستطيع suspend public profile بدون حذف source data.
42. Definition of Done
professional profile يعمل draft/publish/private.
skills تعمل بعلاقات حقيقية وليس JSON فقط.
work history له visibility وتحكم خصوصية.
job offers تعمل send/view/accept/reject/negotiate.
company-to-professional inquiry يعمل بشكل آمن.
publication consent موجود ومرتبط بـ Mall Mirror.
Talent search لا يعرض إلا public data.
moderation/reporting موجودة للملفات العامة.
activity/privacy events تسجل التغييرات الحساسة.
اختبارات الصلاحيات والخصوصية ناجحة.
43. أخطاء ممنوعة
ربط professional_profiles بشركة واحدة داخل users أو profile.
إظهار company_membership أو employee evaluation في السوق تلقائيًا.
استخدام JSON فقط للمهارات بدل skill tables.
إرسال job offer بدون permission وبدون احترام privacy settings.
فتح Talent Marketplace بدون moderation/reporting.
اعتبار reputation score حقيقة نهائية بدل derived metric.
نشر contact info العامة افتراضيًا.
44. الخلاصة التنفيذية
Talent Marketplace في Kabeeri يجب أن يبدأ كطبقة مهنية آمنة ومتحكم فيها، لا كسوق فوضوي. مصدر الحقيقة هو User + Professional Profile + Skills + Work History، أما الظهور العام فيتم عبر consent وmirror وmoderation. القاعدة النهائية: لا موهبة عامة بدون خصوصية، ولا ثقة بدون تحقق، ولا عروض عمل بدون صلاحيات وسجل واضح.
