KABEERI Database File 24
Reviews, Ratings & Reputation Database
نظام التقييمات والمراجعات والسمعة — KABEERI
هذا الملف يصف تصميم قاعدة البيانات الخاصة بمحرك التقييمات والسمعة في Kabeeri، وهو محرك مركزي يخدم Kabeeri Mall وRabet وTalent Marketplace وInternal Marketplace وLegal Partner Network وCommerce لاحقًا.
الهدف هو بناء طبقة ثقة موحدة لا تخلط بين التقييم العام، السمعة المركبة، التوثيق القانوني، الشكاوى، النزاعات، أو الظهور المدفوع.
1. تعريف النظام
Reviews, Ratings & Reputation Engine هو نظام مركزي لتسجيل آراء المستخدمين، تقييماتهم، ردود الجهات، بلاغات المراجعات، وحساب درجات السمعة والثقة عبر أجزاء Kabeeri المختلفة.
النظام لا يخص Kabeeri Mall فقط؛ بل يخدم Business Profiles وServices وProducts وProfessionals وLegal Partners وDevelopers وPlugins/Modules وSellers والعملاء لاحقًا.

3. القواعد الرئيسية
• لا يتم نشر Review عام إلا إذا كانت visibility وstatus تسمح بذلك.
• Rating وحده لا يكفي لبناء Trust Score؛ يجب دمجه مع التوثيق والاستجابة والنزاعات والسلوك.
• Featured أو Sponsored لا تؤثر مباشرة على السمعة أو الثقة، حتى لا تختلط الإعلانات بالتوثيق.
• Moderation يغلب أي Source خارجي أو Sync قادم من Portable/Dedicated.
• البيانات الخاصة مثل invoices وpayroll وinternal messages وemployee evaluations لا تدخل في المراجعات العامة.
• المراجعات التي تؤثر على الثقة أو السمعة يجب أن تكون قابلة للتدقيق عبر audit/activity logs.
• السمعة العامة شيء، والتقييمات الداخلية داخل HR أو ERP شيء آخر لا يظهر للعامة افتراضيًا.

26. Review Submission Flow
User submits review→ validate context and permission→ check duplicate/spam rules→ create review status=pending→ calculate risk/moderation hints→ if clean and policy allows, publish→ update review_subject_summaries→ trigger reputation recalculation→ notify reviewed subject→ log activity/audit if sensitive
27. Review Report Flow
User reports review→ create review_report→ if severity high, open moderation case→ moderator reviews evidence→ action: keep / hide / remove / request edit / escalate→ recalculate summaries and reputation→ notify relevant parties→ log moderation action
28. Reputation Calculation Flow
ReviewPublished or DisputeResolved or VerificationChanged→ queue reputation calculation→ collect ratings, verified reviews, reports, disputes, response rate, verification signals→ calculate score and band→ store factors→ update reputation_scores→ create trust_score_snapshot where applicable→ update Mall ranking signals if public

30. Mall Integration
• Mall يعرض average_rating وreviews_count وtrust_score عندما تكون visibility تسمح.
• Mall لا يعتمد على reviews من قاعدة عميل Portable/Dedicated مباشرة، بل عبر Sync/API وMirror أو مراجعات مركزية.
• Reviews/Ratings جزء من trust layer داخل Kabeeri ويمكن أن تبقى في Central بعد خروج العميل إذا وافق على Mall participation.
• Moderation في Kabeeri Central يمكنها إخفاء مراجعة أو منع ظهورها حتى لو مصدر خارجي أرسلها.
31. Talent Integration
• Professional reputation لا يساوي employee evaluation.
• تقييمات العملاء أو الشركات للمحترف تظهر فقط حسب consent وvisibility.
• التقييمات الداخلية HR لا تُنسخ إلى Talent Marketplace.
• يمكن ربط review بسياق job_offer أو contract_offer أو service delivery.
32. Internal Marketplace Integration
• Package reviews تقيم plugin/theme/module/connector/AI skill.
• Developer reputation لا يعتمد فقط على rating؛ يعتمد على security reviews وsupport response وcompatibility history.
• مراجعات packages يجب أن ترتبط بإصدار version عند الحاجة.
33. Privacy & Data Rules
• لا يسمح بنشر بيانات خاصة داخل review body مثل أرقام هوية أو مستندات قانونية أو بيانات موظفين.
• review body يجب أن يمر على moderation أو automated sensitive data detection عند الحاجة.
• يمكن anonymize reviewer_display_name حسب سياسة البلد أو السياق.
• Deletion قد لا يكون فوريًا إذا ارتبطت المراجعة بنزاع أو سجل قانوني أو audit requirement.
• Legal hold يمنع حذف أو تعديل بعض المراجعات حتى انتهاء القضية.
34. Portable / Dedicated Rules
• إذا خرج العميل Portable، يمكن استمرار reviews العامة كجزء من Kabeeri Mall trust layer.
• Portable يمكنه إرسال public review events فقط عبر signed API، وليس له وصول مباشر لجداول Central.
• Dedicated يرسل usage/trust summaries أو review sync events حسب الاتفاق.
• المراجعات الخاصة أو internal evaluations لا تدخل في أي sync عام.

41. Testing Requirements
• User cannot review private/inaccessible subject.
• User cannot review the same verified context twice unless policy allows.
• Review with private data is flagged or blocked.
• Review report opens moderation case when severity is high.
• Hidden review does not affect public average rating.
• Verified context review receives stronger reputation weight.
• Featured listing does not modify rating or trust score.
• Employee evaluation does not appear in Talent reputation.
• Portable sync cannot publish review without moderation rules.
• Trust score changes when verification expires or dispute remains unresolved.

43. Release Gate
• يمكن إضافة review وربطه بكيان صحيح مع permission/context check.
• average_rating وreviews_count يعملان بدون احتساب hidden/rejected reviews.
• review response يعمل بصلاحيات واضحة.
• review report وmoderation action يعملان مع audit/activity logs.
• reputation score يعاد حسابه بعد review publish أو dispute/verification change.
• Trust Score لا يخلط بين paid featured وverified trust.
• Talent reputation لا يسرّب employee evaluations.
• Portable/Dedicated sync لا يتجاوز moderation أو privacy rules.
44. ملخص القرار
يجب أن يبنى Reviews, Ratings & Reputation كطبقة ثقة مركزية، لا كجداول صغيرة داخل Mall فقط. التقييمات تخدم السوق العام، المواهب، Rabet، الحزم، والشركاء القانونيين، لكنها تحتاج فصلًا واضحًا بين الرأي العام والبيانات الداخلية والسمعة المركبة والتوثيق القانوني.
الهدف في البداية هو reviews basic + responses + reports + summaries، ثم يتم توسيع reputation/trust scoring تدريجيًا مع V3/V4/V5، ومع V6 يمكن الوصول إلى advanced trust and moderation مع disputes وGRC وenterprise governance.
