هذا الملف يصف طبقة قاعدة البيانات الخاصة بحلول القطاعات داخل Kabeeri، بحيث يمكن تثبيت حل صناعي جاهز فوق النواة والـ ERP والـ CMS والـ Commerce والـ BI والـ Workflows، بدون كسر Core أو تحويل النظام إلى مشروع مخصص غير قابل للترقية.
1. تعريف Industry Solutions
Industry Solution هو Package/Suite موجه لصناعة معينة، يجمع Modules وTemplates وWorkflows وDashboards وReports وPermissions وFields وSeeders وDemo Data في حزمة قابلة للتثبيت والإزالة والتحديث.
• ليس مجرد قالب صفحة أو Theme.
• ليس Module منفصل فقط.
• ليس تعديل مخصص داخل Core.
• هو طبقة تركيب منظمة فوق الموديولات الموجودة.
• يجب أن يمر عبر Package governance وpermission disclosure وcompatibility checks.
2. لماذا نحتاج Database مستقلة للحلول الصناعية؟
• لأن قطاعات مثل Real Estate وConstruction وHealthcare وEducation وRetail تحتاج قوالب وحقول وعمليات مختلفة.
• لأن الحل الصناعي قد يفعّل عدة Modules في وقت واحد مثل CRM وProjects وContracts وInventory وBI.
• لأن التخصيص يجب أن يكون قابلًا للتتبع والتصدير والتحديث وليس مجرد كود مخصص.
• لأن Cloud وPortable وDedicated يحتاجون معرفة ما الذي تم تثبيته وما الذي تغير.
• لأن Marketplace يحتاج نشر هذه الحلول كحزم آمنة قابلة للمراجعة والبيع.
3. الفرق بين Solution و Package و Module و Template
المفهوم

Construction Solution
4. المبادئ الحاكمة
• لا يتم تعديل Core مباشرة عند تركيب Solution.
• كل Solution له manifest وإصدار ومراجعة وتوقيع.
• كل Solution يعلن الصلاحيات والبيانات التي يحتاجها قبل التثبيت.
• كل Solution يجب أن يكون tenant-scoped عبر organization_id/company_id/site_id عند الحاجة.
• أي بيانات حساسة مثل المرضى أو الطلاب أو الرواتب تخضع لصلاحيات وخصوصية وAudit.
• يجب دعم install / upgrade / rollback / uninstall مع logs.
• أي Solution يظهر للعميل فقط إذا كان plan يسمح وfeature flag مفعل وmodule installed وpermissions موجودة.
5. يعتمد على ماذا؟
الطبقة
سبب الاعتماد
Core Kernel
الهوية، المؤسسات، الشركات، المواقع، الصلاحيات، الإعدادات، Activity Logs.
Internal Marketplace / Packages
تسجيل الحل كحزمة، المراجعة، التوقيع، التثبيت، التحديث.
Billing / Entitlements
معرفة هل الخطة تسمح بتفعيل الحل الصناعي أم لا.
Modules
تفعيل CRM/Projects/Inventory/Contracts/BI حسب كل قطاع.
Workflows
إنشاء workflows sector-specific مثل approval أو site progress أو patient intake.
BI / Analytics
إنشاء dashboards وKPIs وتقارير القطاع.
Localization / Country Packs
قواعد الدولة والضرائب والخصوصية والفواتير والامتثال حسب البلد.
Security / Compliance
السيطرة على البيانات الحساسة، audit، privacy، access control.
6. ما هو داخل النطاق؟
• Solution registry.
• Solution versions.
• Solution package links.
• Required modules and entitlements.
• Template bundles.
• Workflow bundles.
• Dashboard/report bundles.
• Industry-specific fields.
• Permissions and roles mapping.
• Installations and upgrade logs.
• Demo data and seeders.
• Customizations tracking.
• Industry-specific foundation tables لبعض القطاعات.
7. ما ليس داخل النطاق؟
• بناء كل صناعة بنسبة 100% في V6.
• تخزين كل بيانات الصناعة داخل جدول واحد عام.
• تحويل كل حل إلى fork من Kabeeri.
• تجاوز قواعد Marketplace review/signing.
• تجاوز Country Packs في الضرائب أو الخصوصية أو e-invoicing.
• إدخال بيانات حساسة إلى Mall Mirror بدون consent وقواعد visibility.

12. Installation Flow
Admin selects Industry Solution
→ EntitlementService checks plan
→ Compatibility check runs
→ Required modules checked/installed
→ Permissions disclosed
→ Backup point created if high risk
→ Templates/workflows/dashboards applied
→ Seeders optional
→ Activity/Audit logs recorded
→ Solution status becomes active
13. Upgrade Flow
New solution version available
→ Diff generated
→ Compatibility check
→ Risk level calculated
→ Backup required if medium/high
→ Admin approves upgrade
→ Upgrade steps run queued
→ Applied items updated
→ Customization conflicts reported
→ Rollback available if failure
14. Uninstall Flow
Admin requests uninstall
→ Affected items calculated
→ Data removal policy selected
→ Default: deactivate/archive generated objects
→ High-risk approval required
→ Workflows disabled
→ Dashboards hidden
→ Templates retained as copied customer assets if used
→ Audit log created

18. Portable / Dedicated / Frontend Anywhere Rules
النمط
القواعد
Cloud
كل بيانات solution داخل Cloud DB مع إمكانية تصدير tenant data لاحقًا.
Frontend Anywhere
الواجهة يمكن أن تعرض بيانات عامة فقط عبر APIs/snapshots، ولا تصل لبيانات industry الحساسة.
Portable
يجب تسجيل solution في export registry وتصدير applied_items وsettings وtemplates مع الحفاظ على UUIDs.
Dedicated
نفس schema داخل dedicated DB، مع registry مركزي محدود للتراخيص والتحديثات.
Mall
لا يعرض بيانات industry إلا عبر Mall Mirror وpublication consent. بيانات المرضى/الطلاب/العقود الخاصة لا تنشر.
19. Security & Compliance Rules
• أي حل Healthcare أو Education أو Pharma يعتبر sensitive أو regulated افتراضًا.
• أي وصول لبيانات المرضى أو الطلاب أو payroll أو finance يجب أن يسجل في sensitive access logs.
• AI Skills داخل Industry Solution لا تنفذ write actions خطيرة بدون preview/approval/rollback.
• Country Pack قد يفرض حقولًا أو workflows إضافية حسب الدولة.
• Demo Data لا يجب أن يحتوي بيانات شخصية حقيقية.
• Marketplace review يجب أن يشمل security/business/legal review للقطاعات المنظمة.
20. Acceptance Criteria
• يمكن تسجيل Solution وإصدار وmanifest.
• يمكن تشغيل compatibility check قبل التثبيت.
• يمكن تثبيت الحل على Organization/Company محددة.
• يتم إنشاء applied_items لكل عنصر تم إنشاؤه.
• يتم تسجيل Activity/Audit logs لكل install/upgrade/uninstall.
• يمكن تطبيق templates/workflows/dashboards بدون تعديل Core.
• يمكن تصدير الحل ضمن Portable export.
• يمكن تشغيل demo data safely في sandbox فقط أو بموافقة واضحة.
• لا تظهر بيانات حساسة في Mall أو Search العام.

23. ملخص تنفيذي
Industry Solutions Database تجعل Kabeeri قادرة على تقديم حلول قطاعية جاهزة دون كسر بنية المنصة. الحل الصناعي ليس كودًا مخصصًا عشوائيًا، بل Package/Suite رسمي له manifest، صلاحيات، متطلبات، templates، workflows، dashboards، reports، lifecycle، وقواعد أمن وتصدير. بهذه الطريقة يمكن تثبيت Construction Solution أو Real Estate Solution أو Clinic Solution أو School Solution فوق نفس Core وERP وMarketplace وBI مع الحفاظ على قابلية التحديث والرقابة والتوسع.
