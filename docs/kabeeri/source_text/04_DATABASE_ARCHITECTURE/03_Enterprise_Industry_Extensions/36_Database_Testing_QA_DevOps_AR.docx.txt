1. تعريف Testing / QA / DevOps Operational Database
هذا الملف يصف قاعدة البيانات التشغيلية التي تحفظ حالة الجودة والتجارب والنشر والتحديثات والنسخ الاحتياطية والحوادث والمراقبة داخل Kabeeri. هذه الطبقة لا تبني المزايا نفسها، لكنها تضمن أن أي ميزة يمكن اختبارها، تتبعها، نشرها، مراقبتها، والرجوع عنها عند الحاجة.
النظام يخدم كل الموديولات: Core، CMS، Commerce، ERP، Rabet، Mall، Talent، AI، Integration، Marketplace، Cloud، Portable، وDedicated.
لا يحل محل GitHub Actions أو Sentry أو أدوات CI الخارجية، لكنه يحفظ السجل التشغيلي داخل Kabeeri ويجعل القرارات قابلة للمراجعة.
كل release أو deployment أو migration أو package update أو AI critical change يجب أن يترك سجلا واضحا.
كل اختبار أو فشل أو rollback أو incident يجب أن يكون قابلا للبحث والربط بالنسخة والموديول والعميل والبيئة.
2. الهدف من النظام
منع تحول Kabeeri إلى مشروع ضخم غير مستقر بسبب كثرة الموديولات والتغييرات والتوليد بالذكاء الاصطناعي.
توفير سجل مركزي للـ test runs وQA gates وrelease approvals وdeployment history.
تتبع البيئة التي ظهر فيها الخطأ: local أو testing أو staging أو production أو dedicated أو portable.
تأكيد أن أي عملية خطيرة مثل migration major أو package update أو AI critical change لها backup/rollback plan.
دعم Release Gates من V1 إلى V6، ومنع الانتقال إلى إصدار جديد بدون نتائج جودة واضحة.
توفير أساس لـ Enterprise DevOps لاحقا: DR drills، security scans، compliance reports، release channels، وsupport runbooks.
3. القاعدة الرئيسية
Testable from V1
Observable from V1
Backup before risky changes
Small releases
Rollback-ready
AI-assisted but human-reviewed

8. Flows التشغيلية
8.1 Pre-release Gate Flow
1. Developer creates release draft
2. Run unit/feature/policy/security/package tests
3. Run code quality checks
4. Run migration safety checks
5. Create release notes
6. Run QA gate
7. If passed → approve release
8. If failed → block release until fixed
8.2 Deployment Flow
1. Select release and environment
2. Verify QA gate passed
3. Create deployment_run
4. Create backup if risky
5. Run migration steps
6. Clear cache / restart queue
7. Run health checks
8. Run smoke tests
9. Mark deployment completed or failed
10. If failed → execute rollback plan
8.3 AI-generated Code Review Flow
1. AI generates code suggestion
2. Create ai_code_review_request
3. Run static analysis
4. Run permission/migration/test review
5. Human reviews findings
6. Only approved small change can be committed
7. Run tests locally/CI before merge
8.4 Major Migration Safety Flow
1. Migration detected as risky/destructive
2. Create migration_safety_check
3. Require backup verification
4. Require rollback test where possible
5. Run in staging first
6. Approve production window
7. Record progress and result
8.5 Incident Flow
1. Monitoring event becomes critical
2. Create incident
3. Assign owner
4. Post investigation updates
5. Mitigate or rollback
6. Resolve incident
7. Create postmortem
8. Create action items and link to backlog
8.6 Go-live Checklist Flow
1. Create operational checklist from template
2. Mark required items: content, media, SEO, redirects, forms, backups, DNS, analytics, error logs
3. Block launch if critical items missing
4. Approve go-live
5. Start post-launch monitoring
9. Quality Gates وDefinition of Done
الكود مكتوب ومنظم في Actions/Services وليس business logic داخل Controllers.
الموديل الحساس له Policy واختبارات permission.
المigrations تعمل على قاعدة جديدة ولا تكسر بيانات موجودة.
الـ validation والأخطاء واضحة.
Activity/Audit log موجود للفعل المهم.
النسخة لها release notes: features, fixes, breaking changes, migration notes, security notes, known issues.
كل deployment production له health checks وrollback plan.
كل package update أو AI critical change أو bulk import/delete له backup أو snapshot قبل التنفيذ.
لا ينتقل release gate إلا إذا مرّت الاختبارات الأساسية ولم توجد critical findings مفتوحة.
10. AI Code Review
كل كود يولده AI يجب أن يمر بـ Review ثم tests ثم manual check.
AI لا يبني Module ضخم مرة واحدة؛ العمل يقسم إلى Migration ثم Model ثم Policy ثم Action ثم UI/API ثم Tests ثم Docs.
لا يتم قبول كود AI يغير permissions أو migrations أو billing أو verification أو AI guardrails بدون مراجعة بشرية.
يجب تسجيل finding إذا وجد AI احتمالية تسريب بيانات أو ضعف صلاحيات أو migration مدمرة أو test coverage ضعيف.
القرار النهائي في ai_code_review_requests يكون: approved أو blocked أو requires_changes.
11. Backup / Rollback / DR
Backup مطلوب قبل: package update، major migration، AI critical change، bulk import، bulk delete، theme switch on production، critical workflow activation.
الـ backup لا يعتبر صالحا إلا إذا مر backup_verification_run.
Enterprise يحتاج restore_test_runs دورية وليس مجرد وجود ملفات backup.
Rollback plan يجب أن يكون معروفا قبل deployment وليس بعد الفشل.
DR drills تظهر في V6 مع enterprise DevOps وcompliance reports وrelease channels.
12. Monitoring / Incidents
Health checks الأساسية: app boot, database, cache, queue, storage, scheduler, mail optional, disk space, SSL.
Monitoring لا يقتصر على uptime؛ يجب مراقبة queue failures، failed imports، package install failures، AI usage limits، sync errors، checkout errors، search latency.
كل incident له severity وowner وupdates وpostmortem/action items.
Monitoring events يمكن أن تطلق notifications أو create incident أو rollback suggestion حسب القاعدة.

19. أخطاء ممنوعة
لا تشغل migrations خطيرة بدون backup وmigration_safety_check.
لا تعتمد على AI code بدون review وتشغيل tests.
لا تعمل release بدون scenario demo وrelease notes.
لا تخلط dev data مع production data.
لا تضع secrets في Git أو في DB كنص واضح.
لا تفتح plugin/package updates بدون package validation وrollback plan.
لا تعتبر وجود backup كافيا بدون restore test على الأقل في الإصدارات الحساسة.
لا تجعل CI الخارجي هو مصدر السجل الوحيد؛ يجب حفظ operational summary داخل Kabeeri.
لا تسمح بwaive للـ QA gate بدون سبب وapproval وسجل audit.
لا تقيس الأداء بعد فوات الأوان؛ سجله من البداية ولو بأهداف بسيطة.
20. الخلاصة التنفيذية
قاعدة بيانات Testing / QA / DevOps ليست رفاهية في Kabeeri؛ هي طبقة حماية تشغيلية تمنع انهيار الرؤية الكبيرة بسبب تغييرات صغيرة غير مختبرة. تبدأ بسيطة في V1 مع test runs وsystem status وbackup command، ثم تتوسع في V4 إلى cloud pipeline وmonitoring وpackage review، وفي V6 إلى Enterprise DevOps وDR drills وsecurity scans وcompliance reports وrelease channels. السرعة بالذكاء الاصطناعي لا تعني الاستعجال؛ السرعة الحقيقية هي بناء صغير مستقر قابل للاختبار والرجوع عنه.
ملحوظة توافق مع الملفات السابقة
متوافق مع فلسفة Testing, QA & DevOps: Testable from V1, Observable from V1, Backup before risky changes, Small releases, Rollback-ready, AI-assisted but human-reviewed.
متوافق مع V1: Auth/Organization/Membership/Permission/Site/Page/Media/Activity/Feature Flag tests + installer smoke test + backup command.
متوافق مع V4: Cloud deployment pipeline، automated backups، monitoring، error tracking، package review pipeline، Security Center tests.
متوافق مع V6: Enterprise DevOps، DR drills، security scans، compliance reports، release channels، load/security testing، support runbooks.
