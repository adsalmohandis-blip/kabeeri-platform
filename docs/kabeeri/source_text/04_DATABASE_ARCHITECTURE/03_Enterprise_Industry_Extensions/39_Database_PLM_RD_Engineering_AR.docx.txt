1. تعريف PLM / R&D / Engineering داخل Kabeeri
PLM اختصار Product Lifecycle Management. داخل Kabeeri هو طبقة Enterprise اختيارية لإدارة دورة حياة المنتج من الفكرة إلى التصميم، النسخة، الاختبار، التغيير الهندسي، الاعتماد، ثم التسليم إلى التصنيع أو التجارة أو حلول القطاعات.
R&D هو مساحة البحث والتطوير التي تسجل المشاريع التجريبية، الفرضيات، التجارب، النتائج، النماذج الأولية، وقرارات الانتقال إلى منتج فعلي.
Engineering هو الجزء الذي يدير المتطلبات، المواصفات، الرسومات، الإصدارات، BOM الهندسي، ECO/ECR، اختبارات التصميم، وارتباط المنتج بالمستندات الفنية.
2. لماذا هذا الملف مهم؟
Kabeeri في V6 يحتوي Manufacturing / SCM / EAM foundations، وهذه الطبقات تحتاج مصدرًا منظمًا لتعريف المنتج قبل التنفيذ التصنيعي.
المنتج الهندسي لا يساوي Product التجاري في Commerce، ولا يساوي Item المخزني فقط. المنتج له مواصفات، نسخ، رسومات، BOM، اختبارات، وقرارات تغيير.
بدون PLM، سيتم خلط التصميمات والـ BOM والوثائق داخل Media أو Inventory أو Manufacturing بشكل عشوائي.
هذا الملف يحمي التصنيع والجودة والامتثال من تغييرات غير موثقة في مواصفات المنتج.
يسمح لاحقًا ببناء Industry Solutions لقطاعات مثل التصنيع، الأغذية، الأدوية، المقاولات، الأجهزة، والمنتجات المخصصة.
3. ما ليس ضمن هذا الملف
ليس CAD system كامل.
ليس PDM متقدم لإدارة ملفات CAD الضخمة من البداية.
ليس MES كامل لتشغيل خطوط الإنتاج لحظة بلحظة.
ليس QMS كامل، لكنه يتكامل مع Quality Checks وGRC/Evidence.
ليس Manufacturing BOM النهائي وحده؛ بل يدير Engineering BOM ونسخ المنتج قبل تسليمها للتصنيع.
لا يدخل في V1-V5 إلا كـ placeholders أو روابط مستقبلية.
4. المبادئ الحاكمة
المبدأ
التفسير
Product ≠ Commerce Product
المنتج الهندسي قد يتحول لاحقًا إلى product للبيع، لكنه في PLM يبدأ كمفهوم، تصميم، نسخة، مواصفات، أو مكون.
Engineering BOM ≠ Manufacturing BOM
EBOM يصف التصميم الهندسي، بينما MBOM يصف طريقة التصنيع والتنفيذ.
Revision controlled
أي تغيير في مواصفة أو BOM أو رسم يجب أن يمر بإصدار أو Change Order.
Approval before release
لا يصبح أي item أو BOM أو specification released إلا بعد موافقات محددة.
Documents are linked, not duplicated
الملفات الفنية تحفظ في Media/Documents ويتم ربطها بالكيانات بدل نسخها داخل PLM.
Traceability by default
يجب معرفة: من غير؟ ماذا تغير؟ لماذا؟ ما العناصر المتأثرة؟ ومن وافق؟
Tenant scoped
كل كيان يجب أن يكون organization_id/company_id scoped.
Portable/Dedicated ready
يجب أن تكون البيانات قابلة للتصدير للعميل أو التشغيل في Dedicated بدون كسر العلاقات.

27. Workflows
Workflow
الخطوات
New Product Concept
Create product family → define requirements → create item → attach specs → design review → approve concept
Item Revision
Create new version → edit specs/BOM → submit review → approve → release → supersede old version
ECR/ECO
Submit ECR → triage → impact analysis → create ECO → approvals → implement → verify → close
Prototype Validation
Plan prototype → reserve materials optional → build prototype → run test protocol → record results → decision
Release to Manufacturing
Create release package → validate specs/BOM/tests → approve → create manufacturing handoff → convert to MBOM
Release to Commerce
Approve product public readiness → create commerce handoff → create product draft → publish after business approval

29. Portable / Dedicated / Cloud Rules
Cloud: PLM data داخل قاعدة Kabeeri Cloud مع tenant scoping.
Frontend Anywhere: لا تعرض PLM مباشرة للواجهة العامة إلا public product specs المصرح بها، وغالبًا لا تحتاجه الواجهة.
Portable: يتم تصدير PLM data مع documents linked إذا سمح العميل، مع الحفاظ على UUIDs للـ items/versions.
Dedicated: يفضل للـ PLM في الشركات الحساسة، خاصة إذا كانت بيانات التصميم سرية أو تخضع لقيود قطاعية.
Mall Sync: لا يرسل PLM إلى Mall إلا بيانات عامة مشتقة بعد Commerce/Rabet approval، وليس EBOM أو رسومات خاصة.
Data residency: يمكن ربط PLM بـ Country Packs أو Dedicated إذا كانت الوثائق الفنية لا يجوز خروجها من دولة معينة.
30. Security & Privacy
رسومات CAD والمواصفات الفنية تعتبر sensitive by default.
كل تحميل أو فتح لمستند هندسي حساس يجب تسجيله في sensitive access logs.
ECO approval يحتاج صلاحيات منفصلة ولا يكفي plm.item.manage.
منع حذف versions released؛ يمكن فقط obsolete/supersede.
AI لا يغير BOM أو يطلق release بدون approval.
Export يحتاج approval إذا شمل drawings أو confidential specifications.
ربط الموردين أو المواد البديلة يجب أن يسجل source وapproval.

38. Definition of Done
يمكن إنشاء product family وitem وversion.
يمكن ربط مستندات ورسومات بإصدارات هندسية.
يمكن إنشاء requirements/specifications وربطها بالـ item.
يمكن إنشاء EBOM وإصدارها بعد approval.
يمكن فتح ECR وتحويله إلى ECO مع impact analysis.
لا يمكن تعديل released item version مباشرة.
يمكن تسجيل prototype build وtest results.
يمكن إنشاء release package وتسليمه للتصنيع.
تعمل الصلاحيات والعزل بين organizations/companies.
تظهر logs وaudit events للأفعال الحساسة.
تعمل قواعد Portable/Dedicated export للـ PLM data.
توجد tests أساسية وdocumentation واضحة.
39. ملخص تنفيذي
Kabeeri PLM / R&D / Engineering Database هو امتداد Enterprise اختياري يسمح للمنصة بإدارة المنتجات الهندسية قبل أن تصبح منتجات تصنيع أو منتجات بيع. قوته في الفصل بين التصميم والتصنيع والتجارة، وفي فرض التحكم في الإصدارات والتغييرات والموافقات والأدلة. لا يجب بناؤه مبكرًا، لكنه مهم جدًا إذا كانت Kabeeri ستخدم قطاعات التصنيع، الأغذية، الأدوية، المقاولات، الهندسة، أو المنتجات المعقدة.
